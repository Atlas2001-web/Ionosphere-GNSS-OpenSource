## 1. 它解决什么，边界在哪

| 能做 | 怎么做 | 边界 |
|---|---|---|
| 匿名拉特征参数时间序列 | `https://lgdc.uml.edu/fastchar/getbest?ursiCode=…&charName=…&fromDate=…&toDate=…`（scaled.php 表单 302 过去的就是它） | 只给“最佳可用判读”，大多是 ARTIST 自动判读；要纯人工值看 CS=999 或用 SAO Explorer |
| 每条记录的判读置信度 | 输出自动多一列 `CS`（0–100；999 人工；-1 未知） | 一条记录一个 CS，不是每个参数一个 |
| 站表（URSI 代码 + 坐标） | `https://lgdc.uml.edu/ionoweb/locations`（JSON，131 站） | 旧 `common/DIDBStationList` 30–60 s 超时；站表不告诉你哪天有数据 |
| 电离图列表与 PNG | IonoWeb：`ionoweb/ionolist`、`ionoweb/ionoimage` | PNG 只是图；数值描迹/剖面不在这里 |
| SAO 文件（描迹、剖面、全部 49 个特征） | SAO Explorer 3.6.3（Java 8+）连 DIDBase 的 Firebird 库 | **要账号**：发邮件给 Bodo Reinisch 申请只读账号；网页无匿名 SAO 下载 |
| 许可 | 输出头部与规则页：CC BY-NC-SA 4.0，需致谢站点数据提供方 | **非商业**；商业用途需另谈 |
| 不做 | 实时告警、斜测、TEC 地图 | 这些看 GIM/IRTAM/其他文 |

## 3. 真实命令与输出

### 3.1 fastchar 拉数、旧接口、错名、无数据站、站表（`fetch.sh`，原样）

```bash
#!/usr/bin/env bash
# GIRO fastchar/getbest：匿名 GET，一次拉 WP937 2024-05-01..05-14 的 foF2,hmF2,MUF(D)
set -u
U='https://lgdc.uml.edu/fastchar/getbest?ursiCode=WP937&charName=foF2,hmF2,MUF(D)&DMUF=3000&fromDate=2024%2F05%2F01+00%3A00%3A00&toDate=2024%2F05%2F14+00%3A00%3A00'
curl -s -o wp.txt -w 'HTTP %{http_code}  %{size_download} B  %{time_total} s  %{content_type}\n' "$U"
echo "--- 头部（前 16 行，IP 已打码）"
head -16 wp.txt | sed -E 's/from IP:[0-9.]+/from IP:x.x.x.x/'
echo "--- 数据行数: $(grep -vc '^#' wp.txt)"
echo "--- CS 分布"; grep -v '^#' wp.txt | awk '{print $2}' | sort | uniq -c | sort -k1,1nr
echo "--- 旧接口 DIDBGetValues"
curl -s -o /dev/null -w 'HTTP %{http_code}\n' 'https://lgdc.uml.edu/common/DIDBGetValues?ursiCode=WP937&charName=foF2&fromDate=2024.05.11&toDate=2024.05.12'
echo "--- 旧参数名 MUFD"
curl -s 'https://lgdc.uml.edu/fastchar/getbest?ursiCode=WP937&charName=MUFD&DMUF=3000&fromDate=2024%2F05%2F11+12%3A00%3A00&toDate=2024%2F05%2F11+12%3A10%3A00' | grep -i status
echo "--- 无数据站 BC840"
curl -s 'https://lgdc.uml.edu/fastchar/getbest?ursiCode=BC840&charName=foF2&DMUF=3000&fromDate=2024%2F05%2F11+12%3A00%3A00&toDate=2024%2F05%2F11+13%3A00%3A00' | grep -i status
echo "--- 站表 ionoweb/locations"
curl -s -o loc.json -w 'HTTP %{http_code}  %{size_download} B\n' 'https://lgdc.uml.edu/ionoweb/locations'
```

### 3.4 真实个例：WP937 2024-05-10..12 foF2 耗减（`storm.py`，原样）

```python
# WP937 foF2：CS 过滤 + 平静参考 + 2024-05-10..12 磁暴耗减（NmF2 = 1.24e10·foF2²）
import json, math, statistics as st, urllib.request
from datetime import datetime, timedelta, timezone
rows = []
for ln in open('wp.txt', encoding='latin-1'):
    if ln.startswith('#') or not ln.strip(): continue
    p = ln.split()
    t = datetime.strptime(p[0], '%Y-%m-%dT%H:%M:%S.%fZ').replace(tzinfo=timezone.utc)
    f = float(p[2]) if p[2] != '---' else math.nan
    rows.append((t, int(p[1]), f))
print('总行数', len(rows), '| foF2 缺测(---)', sum(math.isnan(r[2]) for r in rows))
# 过滤：foF2 用 CS>=50 且 !=55（Themens et al. 2022, RSL 22-0001 的 foF2 建议）；999=人工保留；-1 丢
keep = lambda cs: cs == 999 or (cs >= 50 and cs != 55)
good = [r for r in rows if keep(r[1]) and not math.isnan(r[2])]
print('CS 过滤后', len(good), '| 丢弃', len(rows) - len(good),
      '| 其中 CS=0:', sum(r[1] == 0 for r in rows))
# Kp（GFZ）做背景：日最大 Kp
url = 'https://kp.gfz.de/app/json/?start=2024-05-01T00:00:00Z&end=2024-05-13T21:00:00Z&index=Kp'
g = json.loads(urllib.request.urlopen(url, timeout=60).read())
kpd = {}
for t, k in zip(g['datetime'], g['Kp']): kpd.setdefault(t[:10], []).append(k)
print('日最大 Kp:', ' '.join(f"{d[5:]}:{max(v):.1f}" for d, v in kpd.items()))
# 平静参考：05-01..05-09 每 30 min UT 箱的中位数（>=4 个值）
BIN = 30
key = lambda t: (t.hour * 60 + t.minute) // BIN
ref_pool = {}
for t, cs, f in good:
    if t < datetime(2024, 5, 10, tzinfo=timezone.utc): ref_pool.setdefault(key(t), []).append(f)
ref = {k: st.median(v) for k, v in ref_pool.items() if len(v) >= 4}
print('参考箱数', len(ref), '/ 48 | 参考日 05-01..05-09（中位数，非“国际平静日”）')
def dstats(day):
    d0 = datetime(2024, 5, day, tzinfo=timezone.utc); d1 = d0 + timedelta(days=1)
    xs = [(t, f, ref[key(t)]) for t, cs, f in good if d0 <= t < d1 and key(t) in ref]
    dp = [(f - r) / r * 100 for t, f, r in xs]
    tm, fm, rm = min(xs, key=lambda x: (x[1] - x[2]) / x[2])
    return len(xs), st.mean(dp), st.median(dp), tm, fm, rm
print('日期   N   平均Δ%  中位Δ%  最低Δ% @UT (EDT)             foF2/ref MHz  NmF2/ref 1e11 m^-3')
for day in (10, 11, 12, 13):
    n, mn, md, tm, fm, rm = dstats(day)
    print(f"05-{day} {n:4d} {mn:7.1f} {md:7.1f} {(fm-rm)/rm*100:7.1f} @{tm:%m-%d %H:%M}Z ({(tm-timedelta(hours=4)):%m-%d %H:%M} EDT)"
```

### 4.4 CS（ARTIST 自动判读置信度）

- 定义（头部原文）：`Autoscaling Confidence Score (from 0 to 100, 999 if manual scaling, -1 if unknown)`。
- 来源：ARTIST-5 在判读逻辑里穿插的质量判据 + 结果合理性检查汇成一个分数；DIDBase 对所有特征报告（[INAG 说明](https://www.ursi.org/files/CommissionWebsites/INAG/web-73/confidence_score.pdf)）。SAO-4 Group 3 里的两位 “C-level” 与它对应：CS 81–100 → 11，61–80 → 22，41–60 → 33，21–40 → 44，0–20 → 55。
- 阈值：没有官方统一阈值。[Themens et al. 2022（URSI RSL, doi 10.46620/22-0001）](https://doi.org/10.46620/22-0001)：**foF2** 用 CS ≥ 40/50 都可靠但 **55 最差**，建议 “≥ 50 且 ≠ 55”；**hmF2** 只有 75/80/90/95 明显优于气候学，**CS=100 的 hmF2 反而不算好**，0/40/55 比 IRI 还差；foF1 几乎都不如 IRI。很多老脚本用 “CS ≥ 70/75” 一刀切，按这篇对 foF2 偏严、对 hmF2 不够。
- PITHIA 目录的说明：要纯人工（验证过）的值，只取 CS=999，或用 SAO Explorer 的 “manually only” 查询。

| Data File Index | 2(40I3) | 80 个三位整数 = 各 Group 的元素个数，0 表示无；第 80 个是版本号（4） |

| Group 7–33 | 15F8.3 / 40I3 / 120I1 | F2/F1/E 层 O、X 描迹：虚高、真高、幅度、多普勒号、频率 |

## 6. 在工作流里接哪一步

- [A · 一日 TEC](./README.md#a--一日-tec)：foF2/NmF2 做 GIM/IRI 的**地面真值**点；`foF2p` 直接给 IRI 对照；B0/TEC 列可以和 GNSS TEC 比形状。
- [B · 不规则体 / 磁暴](./README.md#b--不规则体--磁暴)：本文 3.4 的 Δ% 流程就是磁暴正/负相的标准做法；配 [space-weather-indices](./space-weather-indices.md) 的 Kp/Dst 定时间轴，配 [cosmic2-ro](./cosmic2-ro.md) 看剖面，Es/fbEs/QF 列可以查闪烁诱因。
- 要批量、多站、多年：先用 3.2 的站表 + 短窗探测筛站，再逐站按月拉 fastchar（别并发）。

## 7. 坑（现象 → 原因 → 修复）

1. **`common/DIDBGetValues` 404** → LGDC 把它下线了（Tomcat “requested resource … not available”），很多脚本（含 [ionosonde-data-downloader](./ionosonde-data-downloader.md)）还在用 → 改用 `https://lgdc.uml.edu/fastchar/getbest?…`（去 scaled.php 表单提交一次就能看到 302 的目标）。fastchar 下其他路径（getvalues、getall、list…）都 404。
2. **`MUFD` 报 `Unknown characteristic name`，只请求它时整个查询 ERROR** → 名字必须和表单一致：`MUF(D)`、`M(D)`、`` h`F2 ``（反引号）、`Type Es` → 照 4.2 抄；URL 里 `(`、`` ` ``、空格最好编码。
3. **把 CS 当成每个参数的分数，或者一刀切 CS ≥ 75** → CS 是整条记录一个；而且各参数的可靠区间不同 → foF2 用 “≥ 50 且 ≠ 55”，hmF2 用 75/80/90/95，999 = 人工，-1 = 未知要单独处理。
4. **HTTP 200 却没数据** → 没数据分两种：`# STATUS: ERROR (No measurement data…)`，或者头部正常、0 行 → 解析时同时检查 `STATUS` 行和数据行数；批量前先短窗探测。
5. **把没出行的时段当成 0 或插值** → 没判出 foF2 的电离图直接不出行（05-11 288 张图只出 205 行），偏偏是磁暴最深时 → 用 IonoWeb `ionolist` 数总张数，报告覆盖率；Δ% 结论里写明缺测。
6. **`common/DIDBStationList` 卡 30–60 s 后 000** → 老接口已不可用 → 用 `ionoweb/locations`（JSON，~10 KB，131 站）；`DIDBYearList` 虽然 200 但忽略参数，别用。
7. **ionoimage 返回 200 但 0 字节** → `time` 带了 `Z`（DIDBaseAccess.js 注释：URL 里不能有 Z）→ 去掉 `Z` 再请求。
8. **想匿名下载 SAO 文件** → 网页只给图和特征参数；数值 SAO 需要 SAO Explorer（Java）+ DIDBase 只读账号（发邮件申请）→ 只要 foF2/hmF2 等就用 fastchar；要描迹/剖面才走 SAO Explorer。
9. **拿去做商业产品** → CC BY-NC-SA 4.0 且“Requires acknowledgement of <站> data provider” → 非商业使用、衍生作品同协议、致谢站点；头部里的规则页旧链接（ulcar…/RulesOfTheRoadForDIDBase.htm）会 meta-refresh 到 `giro.uml.edu/didbase/RulesOfTheRoad.html`。
10. **经度对不上 / 时区错** → 站表和头部经度是东经 0–360（WP937 = 284.5 = −75.5），时间全是 UTC `Z` → 与 COSMIC-2 `edmaxlon`（−180..180）匹配前取 `% 360`；报告本地时间时 EDT = UTC−4。
11. **把磁暴时的“hmF2 ≈ 165 km”当成错判** → 负相磁暴 F2 被削，F1 成为最大峰（G 条件），ARTIST 和 COSMIC-2 都报 160–185 km → 这时 foF2/NmF2 其实是 F1 峰，做 Δ% 要意识到层不一样；autoscaled hmF2 本来就是真高反演值，CS 与 hmF2 可靠度关系弱。
12. **COSMIC-2 与测高仪比出一堆“匹配”** → 中纬站 500 km 内 3 天只有 7 条；而且 ionPrf 高度是 MSL、Abel 反演有球对称假设 → 报告 N 和阈值，别把 N=7 的 r 当统计显著；`edmaxtime` 是 GPS 秒，要减 18 s。
13. **高并发批量拉被限流** → LGDC 是单台 Tomcat，[pyirtam](./pyirtam.md) 实测遇过 429 → 串行、按站按月、加 sleep；本文每次请求 ~1 s。
