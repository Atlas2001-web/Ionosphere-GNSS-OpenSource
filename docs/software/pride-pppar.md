## 1. 场景

### 1.1 它是什么

武汉大学 GNSS 中心 PRIDE 实验室开源的 **多星座 PPP / PPP-AR** 软件包（Fortran + Shell 等，GPL-3.0）。面向**事后**精密单点定位，并尽量 **固定模糊度**，输出坐标/轨迹、对流层 ZTD、残差、模糊度信息等。

### 1.2 什么时候用

- 形变监测、地壳运动、测站坐标时间序列（发表级）。  
- 气象：精密 ZTD / 梯度相关应用。  
- 多星座、多频、高采样（上游支持高至约 50 Hz 量级，以 README 为准）。  
- 需要 **模糊度固定** 而不只是浮点 PPP。  
- 多天连续处理、减弱日界不连续（能力范围内，见上游说明）。

### 1.3 什么时候先别用

- 第一次接触 PPP：先 [RTKLIB](./rtklib.md) 建立产品/天线/潮汐直觉。  
- 只要实时流转换：RTKLIB `str2str` / [BNC](./bnc.md) / [pygnssutils](./pygnssutils.md)。  
- 要 TEC/ROTI 图：换 [PyTECGg](./pytecgg.md) / [IonoMoni](./ionomoni.md)；PRIDE 里电离层主要是**改正与残差**，不是电离层产品引擎。

### 1.4 典型故事

**故事 A：** 研究生要交一篇用 GNSS 测站周解的形变文章。RTKLIB 浮点 PPP 周跳后抖。改用 PRIDE-PPPAR + WUM 产品做 PPP-AR，固定率上去，坐标重复性改善，审稿人问产品与天线模型时答得清。

**故事 B：** 气象组要对比探空与 GNSS ZTD。用 PRIDE 输出 `ztd_` 序列，统一时间与截止高度角，再与再分析场对比。

**故事 C：** 动态船载试验。先 `-m K` 动态 PPP，对照浮点 `-f`，再开 AR，分析海况与遮挡对固定率的影响。

### 1.5 能力边界（据上游 README 归纳，以你检出版本为准）

- 多系统：GPS / GLONASS / Galileo / BDS-2·3 / QZSS。  
- 全频 PPP-AR：在具备对应 OSB/相位钟差产品时，对 GPS/Galileo/BDS 等双频无电离层组合做固定。  
- 高动态、LEO 运动学定轨模式（`L` 等）。  
- 二阶电离层：可用 GIM 产品改正。  
- 多天处理、VMF1/VMF3、MHM 多路径、机器学习模糊度检验等（3.2 线特性，详见上游）。

## 2. 概念

### 2.1 PPP 与 PPP-AR

| 术语 | 人话 |
|---|---|
| PPP | 精密单点定位：单站 + 精密轨道钟差等，估坐标/对流层/钟差等 |
| 浮点 PPP | 模糊度当实数估 |
| PPP-AR | 在相位偏差产品支持下尝试把模糊度固定为整数 |
| OSB / phase bias | 可观测值相关的码/相位偏差产品，AR 关键输入 |
| IF 组合 | 无电离层双频组合；一阶电离层被消掉 |
| 二阶电离层 | 更高阶残差，可用 GIM 等改正 |
| WUM0MGXRAP 等 | 武大等多星座快速产品命名（具体以当前说明为准） |

### 2.2 定位模式（`-m`，助记）

| 码 | 含义（人话） |
|---|---|
| S | 静态 |
| K | 动态（kinematic） |
| P | 分段常值等（见帮助） |
| F | 坐标固定（应用向） |
| L | LEO |

以 `pdp3 -H` 为准。

### 2.3 产品依赖直觉

没有匹配的轨道/钟差/偏差/ERP/姿态等，AR 会失败或不应开启。**先浮点跑通，再开 AR。**

### 2.4 电离层在 PRIDE 中的角色

- 默认 IF 组合：一阶电离层被组合掉。  
- 可启用二阶改正（GIM）。  
- 输出残差可间接反映扰动，但**不是** ROTI 产品替代。

### 2.5 与 IGS 惯例

支持 Bias-SINEX、IGS20、ORBEX、RINEX 4 等方向的兼容（以上游为准）。天线 PCO/PCV、潮汐、框架要与产品一致，否则「软件没错但坐标系叙事错」。

## 3. 安装

### 3.1 依赖

bash、make、**gfortran**、gcc、wget 或 curl。建议**普通用户家目录**安装（安装脚本常拒绝 `/root`）。

### 3.2 步骤

```bash
git clone https://github.com/PrideLab/PRIDE-PPPAR.git
cd PRIDE-PPPAR
bash install.sh
# 二进制多在 ~/.PRIDE_PPPAR_BIN/ ；按提示加入 PATH
echo 'export PATH="$HOME/.PRIDE_PPPAR_BIN:$PATH"' >> ~/.bashrc
source ~/.bashrc
pdp3 -V
pdp3 -H | head
```

### 3.3 GUI（可选）

仓库 `gui/` 轻量界面；Windows 用户另见上游说明。教学仍建议先 CLI。

### 3.4 验证

```bash
which pdp3
pdp3 -V
ls "$HOME/.PRIDE_PPPAR_BIN" | head
```

### 3.5 编译失败

| 现象 | 处理 |
|---|---|
| 无 gfortran | `sudo apt install gfortran`（或等价） |
| 装到 /root | 换普通用户 |
| macOS sed 问题 | 关注上游 install 修复版本 |
| 权限 | 不要乱 sudo make install 到系统 |

## 4. 逐步例子 + 预期输出

### 4.1 先跑官方 example

按仓库 `example/` 与安装提示跑通。**预期：** 生成按年/年积日组织的结果目录，出现 `kin_`/`pos_`/`ztd_`/`res_` 等（具体前缀以上游为准）。

### 4.2 静态 PPP-AR

```bash
pdp3 -m S data/site0010.24o
# 或显式时间与站名（格式以 -H 为准）
# pdp3 -m S -n site -s 2024/001/00:00:00 -e 2024/001/23:59:30 data/site0010.24o
```

**预期：** 自动尝试下载/使用产品（网络允许时）；结束有摘要；结果目录非空；AR 相关日志显示固定尝试。

### 4.3 动态

```bash
pdp3 -m K data/rover0010.24o
```

**预期：** `kin_` 轨迹文件；高遮挡时固定率下降——属现象而非一定软件坏。

### 4.4 强制浮点对照

```bash
pdp3 -m S -f data/site0010.24o
```

**预期：** 无 AR 或 AR 关闭；用于证明「产品链路先通」。

### 4.5 系统与频率

```bash
pdp3 -m S -sys GREC3 -frq "G12 E15 C26" data/site0010.24o
```

**预期：** 仅使用声明系统/频率；缺对应 OSB 时 AR 变差——查产品与 `-frq` 一致性。

### 4.6 配置文件

```bash
cp table/config_template ./config_my
# 编辑天线、截止高度角、产品路径等
pdp3 -cfg ./config_my data/site0010.24o
```

### 4.7 二阶电离层 / GIM（若版本支持）

按配置模板中的开关与 GIM 路径设置。**预期：** 残差或改正项有相应体现；需自备 IONEX。

### 4.8 多天

按上游多天与 DOCB 说明准备连续日观测与对齐产品。**预期：** 日界连续性优于「逐日独立浮点再硬拼」。

### 4.9 绘图

```bash
# 仓库常提供 plotkin.sh 等；以你版本脚本名为准
plotkin.sh  # 或 bash script/plotkin.sh ...
```

**预期：** 轨迹/残差图；失败时先查结果文件是否生成。

### 4.10 与 RTKLIB 对照日

同一站日：RTKLIB 浮点 PPP vs PRIDE 浮点 vs PRIDE AR。**预期：** 框架/天线对齐后，静态水平差异在厘米到亚厘米量级讨论（视条件）；若差几米，先查天线高/ECEF/产品日。

## 5. 格式

### 5.1 输入

- RINEX OBS 2/3/4  
- 广播星历（常自动/可预置）  
- 精密轨道、钟差、bias、ERP、姿态/ORBEX 等（WUM0MGXRAP 等）  
- 天线 antex、海洋负荷等表格（安装目录 `table/`）

### 5.2 输出（常见前缀，以版本为准）

| 前缀/类 | 内容 |
|---|---|
| kin_ | 动态轨迹 |
| pos_/static | 静态坐标解 |
| ztd_ | 对流层 |
| res_ | 残差 |
| amb_ | 模糊度相关 |
| 日志 | 运行与 AR 摘要 |

目录常按 `年/年积日` 组织。

### 5.3 不做

- 不输出 ROTI/STEC 产品标准文件（即使残差可用）。  
- 不替代 QC：前置 [Anubis](./anubis.md)/[GFZRNX](./gfzrnx.md)。

## 7. 常见坑（≥12）

1. 产品 FTPS 失败：URL 变更/网络；改手动下载或换镜像。  
2. AR 固定率低：缺 bias、频点与 OSB 不一致；先 `-f`。  
3. 与 RTKLIB 差很大：天线、潮汐、框架、产品不一致。  
4. 多天跳变：日界模糊度/DOCB/产品未对齐。  
5. 编译失败：无 gfortran / root 安装。  
6. 站名/文件名不规范：RINEX 命名与 `-n` 不一致。  
7. 截止高度角过低：多路径害 AR。  
8. 高采样无匹配产品采样策略：读上游高采样说明。  
9. GLONASS 权重/频偏：多系统配置需谨慎。  
10. 忽略天线 PCV：尤其精密静态。  
11. 把 PRIDE 当实时引擎：它是事后包。  
12. 旧版不认新 WUM 命名：升级 3.x。  
13. 磁暴日苛责软件：先看 ROTI/闪烁。  
14. 路径空格/中文目录：尽量 ASCII 路径。  
15. 只看最后坐标不看残差：漏掉系统误差。  
16. GUI 与 CLI 配置不一致：以实际跑的为准。
