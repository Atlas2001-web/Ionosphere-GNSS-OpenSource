## 1. 场景

### 1.1 它是什么

**G-Nut/Anubis** 是面向 GNSS 数据中心与用户的 **质量检查（QC）** 工具。版本线含 Free / Pro / Real-Time。本页只讲 **Anubis Free**（撰写时常见标称 2.3 量级，Linux，以下载页为准）。

它回答：数据全不全？缺口在哪？多路径重不重？哪一系统老掉链？输出 **XTR / XML** 报告——**不是** TEC，**不是** 精密定位引擎。

### 1.2 何时用

- 站网日检、入库前门槛。  
- 投稿前证明观测可用。  
- TEC/PPP 之前的「数据体检」。  
- TEQC 老旧后的常见替代组合之一（与 GFZRNX 搭配）。

### 1.3 何时不用

- 只要拼接/抽稀/改采样 → [GFZRNX](./gfzrnx.md)。  
- 只要读进 Python → [georinex](./georinex.md)。  
- 要 ROTI → [IonoMoni](./ionomoni.md)/[OASIS](./oasis-roti.md)。  
- 要实时流 QC 仪表盘 → 评估 Anubis RT/商业档或其他运维栈。

### 1.4 与 GFZRNX 分工

| 工具 | 动词 |
|---|---|
| GFZRNX | **改**文件 |
| Anubis | **评**文件 |

推荐顺序：GFZRNX（必要整理）→ Anubis QC → 科学软件。

### 1.5 故事

数据中心早晨批量：对昨日 RINEX 跑 lite QC，缺口超阈邮件告警；坏站剔除后再跑 PPP/TEC，避免「算法论文其实是数据洞」。

## 2. 概念

### 2.1 QC 模式（人话）

| 模式 | 人话 |
|---|---|
| thin | 偏头信息/元数据 |
| lite | 定量：缺口、完整性 |
| full | 更综合：可含更多算法相关 QC、简易 SPP 等 |

在 XML 配置中切换（键名以手册为准）。

### 2.2 报告

- **XTR**：详细文本，适合 grep。  
- **XML**：汇总，适合机器解析。  
- 社区绘图：`plot_anubis.pl`（无官方支持承诺）。

### 2.3 Free vs Pro/RT

Free：事后 RINEX QC 主力。  
Pro/RT：流、编辑/翻译、组网仪表盘等——本页不展开，官网为准。

### 2.4 典型指标直觉

完整性、周跳/缺口、多路径验后指标、信噪比、各系统可见性、码/相位可用性等（具体字段见 XTR 手册段）。

## 3. 安装

1. 打开下载页（可能需注册），取 **Free / Linux** 包或源码。  
2. 将 `anubis` 放入 `PATH`。  
3. 冒烟：

```bash
anubis -h | head
anubis -X | head
```

OS X / Windows 二进制条件以官网为准。

---

## 4. 逐步例子 + 输出

### 4.1 导出默认 XML

```bash
anubis -X > anubis_qc.xml
```

**预期：** XML 骨架含 inp/out/qc 等段。

### 4.2 编辑路径后运行

编辑 `<inp>` 的 OBS/NAV，`<out>` 的 xtr/xml 路径，然后：

```bash
anubis -x anubis_qc.xml
# 或 anubis < anubis_qc.xml
```

**预期：** 生成 `.xtr` 与 `.xml`；终端有进度/摘要。

### 4.3 命令行覆盖路径

```bash
anubis -x anubis_qc.xml \
  :inp:rinexo=data/site0010.24o \
  :inp:rinexn=data/brdc0010.24n
```

（键名以 `anubis -h` / 手册为准。）

### 4.4 先 lite 后 full

先 lite 看完整性；通过后再 full。**预期：** full 更慢、报告更长。

### 4.5 grep XTR

```bash
grep -E 'MP|gap|SNR|Summary' site0010.xtr | head
```

### 4.6 出图（社区）

```bash
# 自 https://www.pecny.cz/sw/plots/anubis/ 取得脚本
perl plot_anubis.pl site0010.xtr
```

### 4.7 批量日检骨架

```bash
for f in data/*.24o; do
  anubis -x anubis_qc.xml :inp:rinexo="$f" || echo "FAIL $f"
done
```

### 4.8 与 georinex 交叉

Anubis 报某小时缺口 → georinex 读同时段确认空历元。**预期：** 两者一致才可信。

## 7. 常见坑（≥12）

1. 路径相对/权限 → 几乎无输出。  
2. 工具选错：想抽稀却开 Anubis。  
3. Free 无实时菜单。  
4. full 报告爆炸 → 先 lite。  
5. 缺 NAV 导致部分检查弱。  
6. Hatanaka 未解压。  
7. RINEX3 系统过滤误解。  
8. 把 QC 当修复：Anubis 评不改（改用 GFZRNX）。  
9. 忽略多路径却怪算法。  
10. 旧 TEQC 指标不可逐字段横比。  
11. XML 编码/CRLF 损坏。  
12. 批量覆盖输出文件名。  
13. 只看摘要不看分系统。  
14. 磁暴日「变差」可能是真空间天气。  
15. 版本与手册不一致。  
16. 未引用/未遵守许可。

## 9. 长附录

### 9.1 日检门槛示例（自定义）

- 完整性 < 80% 告警  
- 某系统全缺告警  
- 多路径指标超历史分位告警  

### 9.2 XTR 阅读顺序

头信息 → 完整性 → 分系统 → 多路径/SNR → 总结。

### 9.3 练习

1. 对同一文件 thin/lite/full 各跑一次比时间。  
2. 人为删一小时观测再 QC。  
3. 与 GFZRNX 抽稀后 QC 对比。  
4. 解析 XML 做周报。  

### 9.4 术语

QC、XTR、MSM 完整性、多路径、周跳、SPP 验核……

### 9.5 安全与合规

下载需注册时用机构邮箱；不要重分发商业二进制。

### 9.6 与数据中心工作流

入库 → Anubis → 状态库 → 仅合格进 PPP/TEC 队列。
