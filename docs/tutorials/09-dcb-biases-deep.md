## 0. 这堂课要解决的「课堂谜题」

你学完双频几何无关组合后，兴冲冲跑出一条 STEC 时间序列，和同组同学、或和公开 GIM 产品一比，发现：

- 曲线**形状**很像（白天高、夜里低，磁暴时一起抬升）；
- 但整条曲线仿佛被**竖直平移**了 3～10 TECU，甚至更多；
- 有时两台接收机放在同一屋顶，同一时段，差一截几乎平行的常数。

很多人第一反应是：「我算错了」或「电离层真的不一样」。更常见的真相是：**尺子两端粘了橡皮泥**——也就是 **DCB（Differential Code Bias，差分码偏差）** 及其亲戚（接收机 IFB、码类型不一致、相位弧段常数、产品基准不对齐）。

本讲把这件事从「听说过」推到「知道什么时候可以假装不管、什么时候必须较真、怎么和 IGS 产品握手」。

## 1. 术语表（每个词都先钉死）

| 术语 | 一句话定义 | 初学者易混点 |
|---|---|---|
| **TEC** | Total Electron Content，总电子含量：沿路径积分的电子柱密度 | 「TEC」常被随口说成 VTEC；问清楚是斜的还是垂直的 |
| **STEC** | Slant TEC，斜路径 TEC：卫星→接收机真实路径上的积分 | 低高度角 STEC 往往远大于 VTEC |
| **VTEC** | Vertical TEC，天顶方向等效 TEC：常由 STEC 经映射得到 | 映射假设错了，VTEC「看起来漂亮」也不物理 |
| **TECU** | TEC 的常用单位：\(1\,\mathrm{TECU}=10^{16}\,\mathrm{el\,m^{-2}}\) | 和米、纳秒之间要换算，别直接加减 |
| **几何无关组合（GF）** | 双频观测量线性组合，消除几何距离等公共项，留下电离层 + 频率相关偏差 | 「无关」不是「无偏差」 |
| **DCB** | Differential Code Bias：两频率（或两码类型）之间的硬件码延迟差 | 不是随机噪声，短时段内更像慢变常数 |
| **卫星 DCB** | 卫星端两频码延迟差（换算到 TEC/距离域后进入 GF） | 全球网可当公共参数估；单站也可用产品改正 |
| **接收机 DCB / IFB** | 接收机端类似的频率相关码延迟差（IFB = Inter-Frequency Bias，常与接收机 DCB 混称） | 换机、换固件、换天线后可能跳变 |
| **绝对 TEC** | 带物理零点意义的 TEC 数值（例如「此刻 42 TECU」） | 对 DCB / 基准极敏感 |
| **相对 TEC / 扰动 TEC** | 相对某参考时段、或差分掉慢变后的变化量 | 常数 DCB 常可近似忽略 |
| **OSB / UPD** | Observable-Specific Bias / Uncalibrated Phase Delay：更细的码/相位偏差产品 | PPP、多系统场景更常见；科学 TEC 课上先抓住 DCB 即可 |
| **IONEX / GIM** | 全球/区域电离层图交换格式与产品；分析中心常**同时**估 TEC 与 DCB | 不同中心绝对水平可差数 TECU |
| **码类型（RINEX）** | 如 C1C、C1W、C2W…：不同跟踪通道/相关器定义 | DCB 产品必须和你用的码对对齐 |

把表读两遍。后面所有「平移」「基准」「相对 vs 绝对」都建立在这些定义上。

## 2. 核心类比：橡皮尺（rubber-ruler）

想象你要量「雾的厚度」（电离层电子含量）。你有一把双频尺：

- 尺身本身可以很好地消掉「你站的位置到卫星的几何距离」——这就是几何无关组合的功劳；
- 但尺子**两端**（卫星端、接收机端）各粘了一小段不知道多长的**橡皮泥**；
- 橡皮泥长度几乎不随「雾厚」变化，短时段内也几乎不随时间扭动。

于是：

1. 你测到的「雾厚」= 真雾厚 + 两端橡皮泥之和（再加噪声）；  
2. 雾一天之内从薄变厚再变薄，曲线形状还在，但**整条曲线被垫高或垫低**；  
3. 若你只关心「今天下午比上午厚了多少」，两端橡皮泥相减后抵消——相对变化仍可用；  
4. 若你要报「现在是 45 TECU」并和 IRI、别的分析中心、别的接收机比绝对值，就必须量出橡皮泥，或大家约定同一把「零点尺」。

**这段两端的橡皮泥，就是 DCB（及同类硬件延迟差）在课堂里的形象。**

再补一个类比：相位几何无关组合像「更干净的游标」，但锁住的是**相对刻度**——每段连续弧有一个未知常数（模糊度），周跳会换一段新常数。伪距给绝对感，相位给平滑感；两者钉在一起时，DCB 与模糊度会抢「谁吸收常数」的锅。

## 3. 几何无关组合里，偏差到底藏在哪

回顾伪距几何无关组合的教学写法（符号因文献略有出入，直觉不变）：

\[
P_{GF} = P_1 - P_2 \propto \mathrm{STEC} + b^{\mathrm{sat}} + b_{\mathrm{rcv}} + \varepsilon
\]

- \(P_1,P_2\)：两个频率上的伪距；  
- \(b^{\mathrm{sat}}\)：卫星端贡献（与卫星 DCB 对应，单位需统一到米或 TECU）；  
- \(b_{\mathrm{rcv}}\)：接收机端贡献；  
- \(\varepsilon\)：噪声、多路径、未模型化项。

相位组合更平滑，但多一个**弧段常数**；周跳或失锁会让常数换一段，看起来像 TEC「台阶」——那不是电离层瞬间塌了，是尺子换了零点。

### 3.1 卫星 DCB vs 接收机 DCB：谁更「公共」？

| | 卫星 DCB | 接收机 DCB / IFB |
|---|---|---|
| 物理位置 | 卫星载荷/天线链路两端频延迟差 | 接收机前端、相关器、固件链路 |
| 网解时角色 | 对全球站网近似**公共**；一颗星一个（或按码对） | 每台接收机一个；站网越大越能与卫星端分离 |
| 单站用户 | 优先用公开产品改正 | 常作为未知数与映射/VTEC 一起估，或与参考站差分削弱 |
| 典型「出事」信号 | 换用错误分析中心产品、码对不匹配 | 换机后 TEC 整天平行跳一截；两机同站差常数 |

课堂口诀：**卫星 DCB 像「天上那把尺的出厂公差」；接收机 DCB 像「你手里这把尺的出厂公差」。两把尺的公差都会进读数。**

### 3.2 为什么绝对 TEC 会「整段平移」？

因为在短时段（数小时到一两天）内，\(b^{\mathrm{sat}}+b_{\mathrm{rcv}}\) 近似常数。常数进不了「形状」，只进「零点」。于是：

- 日变化形态、TID 波纹、磁暴抬升的**相对幅度**往往仍有用；  
- 「今天中午 45 TECU」这种**绝对数字**会跟着常数走；  
- 把未改正的 STEC 拿去和 IGS GIM、IRI 比绝对值，等于拿两把没对齐零点的尺比长度。

### 3.3 相对 vs 绝对：一张决策表

| 你的科学/工程目标 | DCB 要多较真？ | 理由 |
|---|---|---|
| ROTI、相位抖动、扰动检测 | 通常低 | 差分/高通后常数几乎消失 |
| 差分 TEC、相对增强百分比 | 中低 | 注意：若用映射后的 VTEC 再比，映射误差仍在 |
| 单站绝对 VTEC 气候学 | 高 | 零点直接进气候均值 |
| 多站融合建 GIM | 高 | 偏差会泄漏进图与梯度 |
| 与 IRI / 掩星积分比绝对值 | 高 | 否则「模式偏差」其实是尺子偏差 |
| PPP 无电离层组合定位 | 另一条路 | 见第 6 节；不是把 DCB 估成 TEC |

## 4. 和 IGS / 分析中心产品怎么「握手」

### 4.1 为什么 GIM / IONEX 里也有 DCB？

IGS 电离层工作组及相关分析中心做全球 GIM 时，观测方程里同时有：

- 空间部分：格网或球谐等表示的 VTEC（或等价参数）；  
- 偏差部分：一批卫星 DCB、一批接收机 DCB。

地图和偏差是**耦合解**出来的。必须施加基准约束，例如：某组卫星 DCB 之和为 0，或固定某接收机——否则「整网平移」不可观。

因此：

1. 你下载的 IONEX 头文件、伴随 DCB 文件、或分析中心说明里，常能看到偏差相关信息；  
2. 不同中心（如 CODE、JPL、CAS、UPC、WHU、GFZ 等路线）的绝对 TEC 可以差数 TECU——部分来自**基准、观测选择、映射与约束策略**，不全是「谁家电离层更真」；  
3. 比对两家 GIM：先看形态与梯度、地方时结构，再抠绝对水平；组合产品思路可参考 `UWM-IGS-Iono-Combination`。

### 4.3 对齐产品时必问的四个问题

1. **码对**：产品对应 C1W/C2W 还是 C1C/C2W？你的 RINEX 观测量类型是什么？  
2. **单位**：ns、米，还是已换算的 TECU？符号约定（\(P_1-P_2\) 还是反过来）？  
3. **基准**：哪个卫星集合被约束？能否与你的接收机估计同基准相加？  
4. **时间**：日解、快速、实时？换代日是否有跳变？

四个问题答不上，就不要把「和 CODE 差 6 TECU」写成「我的算法烂」。

## 5. 教学版处理流程（五步，每步说清失败模式）

### 步骤 A：选观测量

- **伪距 GF**：无模糊度、有绝对感，但噪声与多路径大。  
- **相位 GF**：平滑，但有弧段常数。  
- **实务**：相位平滑伪距，或「相位相对 + 伪距钉绝对」。

失败模式：只用伪距却期望像文献里一样光滑；或只用相位却拿绝对 TECU 去和 GIM 比。

### 步骤 B：连弧与周跳

相位跳了 → TEC 出台阶。先探测/修复周跳，或分段估常数。

失败模式：把周跳台阶解释成「突发空间天气」。

### 步骤 C：估 / 改正偏差

- 卫星端：优先用公开 DCB/OSB 类产品改正（入口见上表与 `Gkit-Bias`）。  
- 接收机端：单站常当未知数；多站网可把卫星 DCB 当公共参数。  
- TEC 主线工具（估 STEC）：`gnss-tec`、`pygnss-tec`、`tec-suite`、`Seemala-GPS-TEC`、`Okoh-MATLAB-TEC-from-RINEX`、`IONOLAB-TEC-Software`。

失败模式：混用不同分析中心的卫星 DCB，却把自己的接收机 DCB 钉在另一套基准上。

### 步骤 D：对齐产品基准

和 CODE/CAS/JPL/WHU 等比时，统一码对、单位、符号、约束。读 IONEX 可用 `ionex`、`ionex-rs`、`ionex_reader`、`ionex-analyzer`。

### 步骤 E：按目标决定较真程度

回到第 3.3 节决策表。写报告时显式声明：「本结果为相对 TEC」或「绝对 TEC，DCB 来源为××」。

## 6. 和定位的关系（别和 06 打架）

[06-iono-positioning.md](./06-iono-positioning.md) 里，PPP 常用**无电离层组合（IF）**：本质是绕开一阶电离层，不是把 DCB 估成科学 TEC。  
目标是「电子含量科学」→ TEC/GIM 路线；目标是「位置」→ IF/双频消电离层往往更直接。

| 目标 | 典型思路 | 目录可对号 |
|---|---|---|
| 科学 TEC / GIM | 显式估/改正 DCB，输出 STEC/VTEC | `gnss-tec`、`ionex`、`SH-GIM`、`mosgim`、`mosgim2`、`m_gim`、`M_GIM` |
| 精密定位 | IF 组合，或估计电离层参数辅助模糊度 | `RTKLIB`、`gLAB`、`GAMPII-GOOD`、`PRIDE-PPPAR`、`PPP-RTK-Ionosphere` |

两条路都碰偏差，但参数名字与约束习惯不同——写论文时不要把「PPP 的 OSB」和「GIM 的卫星 DCB」混成同一个故事。

## 7. 常见误区（请逐条打假）

1. **「我已经双频了，所以没有偏差」**  
   双频消的是几何与对流层等公共项，**不是**频率相关硬件延迟差。

2. **「DCB 会随 TEC 日变化扭来扭去」**  
   短时段内更像慢变/常数。若你的「DCB」跟着地方时剧烈扭，多半是映射、多路径或弧段断裂被误吸收。

3. **「所有码类型共用同一套 DCB」**  
   C1C、C1W、C2W… 定义不同。RINEX 类型必须和偏差产品对齐。

4. **「两机同站差 5 TECU 且平行 = 电离层真差 5」**  
   优先怀疑接收机 DCB/IFB 或码类型。

5. **「换固件后 TEC 跳了 = 空间天气」**  
   先查硬件延迟是否变了。

6. **「伪距 TEC 与相位 TEC 绝对水平可直接比」**  
   没处理模糊度/平滑策略时，比的是两套零点。

7. **「和某家 GIM 差 8 TECU 就是我错了」**  
   先查基准与时间对齐；中心之间本身有差（见 `UWM-IGS-Iono-Combination` 一类工作）。

8. **「低高度角 DCB 不稳定 = 硬件坏了」**  
   多半是映射与多路径，别全推给硬件。

## 9. 测验（建议闭卷写 15 分钟）

**Q1.** 用橡皮尺类比，说明为什么相对 TEC 对常数 DCB 不敏感，而绝对 TEC 敏感。（约 80 字）

**Q2.** 卫星 DCB 与接收机 DCB 在「全球网解」和「单站解」中的处理策略有何不同？

**Q3.** 两台接收机同一测站、同一时段，STEC 差约 5 TECU 且几乎整天平行。更可能原因是什么？列出至少两个验证步骤。

**Q4.** 你只关心磁暴期间 TEC **相对**增强。DCB 估不准何时仍会致命？

**Q5.** RINEX 用 C1C/C2W，却套了另一对码的 DCB 产品，后果是什么？

**Q6.** 指出本仓库中：两个用于 RINEX→STEC 的条目、两个用于读 IONEX 的条目、两个 IONEX/GIM 数据入口。（必须写 `PROJECTS.json` 中的精确 `name`）

**参考要点（自查，勿死记）：**  
Q1：常数加在两端，差分掉。Q2：卫星端公共/产品改正；接收机端站相关未知数。Q3：接收机 DCB/码类型；换机对比、码类型检查、与公开卫星 DCB 产品对齐后再比。Q4：若相对是对错误映射后的 VTEC、或跨站融合前未统一基准。Q5：系统零点错误。Q6：例如 `gnss-tec`/`Seemala-GPS-TEC`；`ionex`/`ionex-analyzer`；`CDDIS-IONEX`/`JPL-IONEX-Rapid`（答案不唯一，名称必须真实存在）。

## 12. 单位换算直觉（怕公式的人也可以读）

课堂里常把 DCB 说成「几纳秒」。电离层延迟与 TEC 近似成正比，双频组合里「1 ns 量级的差分延迟」可以换算成数 TECU 量级的等效偏差（精确系数取决于频率对，GPS L1/L2 与 BDS/Galileo 不同）。你不必在本课背公式，但必须建立数量级直觉：

- **差 1～3 TECU**：在安静中纬日变化里可能只是「零点争议」；在低纬白天高 TEC 背景下，相对比例更小，但仍足以毁掉「与 IRI 绝对值比对」的结论。  
- **差 5～10 TECU**：两机同站平行差这么多，几乎肯定先查接收机端与码类型，而不是先写「局部电离层异常」。  
- **符号反了**：有人把 \(P_1-P_2\) 与产品定义反号，结果「改正」变成「加倍」——曲线形状仍像，零点更歪。

练习：把你软件输出的 STEC 单位（TECU 还是米？）写在笔记本第一行；再把所用 DCB 产品的单位写在第二行；第三行写换算是否在软件内完成。三行对不齐，就不要开始画「科学结论图」。

## 13. 「相对」也有陷阱：四种看起来像相对、其实仍怕 DCB 的情况

1. **跨站差分但未统一卫星 DCB 产品版本**  
   两站各自改正了不同代的卫星 DCB，差分后残留系统差。

2. **先映射成 VTEC 再做「相对」**  
   高度角、壳高、梯度会把误差变成非常数；你以为减掉了零点，其实减掉的是「错误零点 + 错误映射」。

3. **把不同弧段的相位常数当「相对物理」**  
   弧段拼接不好，相对变化里会出现假台阶。

4. **用一家 GIM 做参考，再宣称自己的「相对偏差」**  
   参考本身含其 DCB 基准；你在测「我与他的差」，不是「我与真理的差」。

所以：口说「我做相对」时，请补半句——**相对的是什么参考、在哪一处理域（STEC 还是 VTEC）差分。**

## 14. 和下一课的接口（预习 10）

下一课 [10-build-gim-workflow.md](./10-build-gim-workflow.md) 会把多站 STEC 收成 GIM。你会看到：DCB 估不好，误差不会「均匀糊在网上」，而可能变成：

- 某些测站周围系统性偏高/偏低；  
- 球谐低阶项吸收网级偏差，看起来像「全球平均 TEC」错了；  
- 边界站稀疏区出现假梯度。

因此第 9 课不是选修附录，而是建图流水线的**调味步骤**：菜没洗干净（QC）和不放盐（DCB）一样，最后那盘「漂亮的图」可能不可吃。
