## 0. 这堂课要解决的「课堂谜题」

你学完双频几何无关组合后，兴冲冲跑出一条 STEC 时间序列，和同组同学、或和公开 GIM 产品一比，发现：

- 曲线**形状**很像（白天高、夜里低，磁暴时一起抬升）；
- 但整条曲线仿佛被**竖直平移**了 3～10 TECU，甚至更多；
- 有时两台接收机放在同一屋顶，同一时段，差一截几乎平行的常数。

很多人第一反应是：「我算错了」或「电离层真的不一样」。更常见的真相是：**尺子两端粘了橡皮泥**——也就是 **DCB（Differential Code Bias，差分码偏差）** 及其亲戚（接收机 IFB、码类型不一致、相位弧段常数、产品基准不对齐）。

本讲把这件事从「听说过」推到「知道什么时候可以假装不管、什么时候必须较真、怎么和 IGS 产品握手」。

## 1. 术语表（每个词都先钉死）

| 术语 | 一句话定义 | 初学者易混点 |
|---|---|---|
| **TEC** | Total Electron Content，总电子含量：沿路径积分的电子柱密度 | 「TEC」常被随口说成 VTEC；问清楚是斜的还是垂直的 |
| **STEC** | Slant TEC，斜路径 TEC：卫星→接收机真实路径上的积分 | 低高度角 STEC 往往远大于 VTEC |
| **VTEC** | Vertical TEC，天顶方向等效 TEC：常由 STEC 经映射得到 | 映射假设错了，VTEC「看起来漂亮」也不物理 |
| **TECU** | TEC 的常用单位：\(1\,\mathrm{TECU}=10^{16}\,\mathrm{el\,m^{-2}}\) | 和米、纳秒之间要换算，别直接加减 |
| **几何无关组合（GF）** | 双频观测量线性组合，消除几何距离等公共项，留下电离层 + 频率相关偏差 | 「无关」不是「无偏差」 |
| **DCB** | Differential Code Bias：两频率（或两码类型）之间的硬件码延迟差 | 不是随机噪声，短时段内更像慢变常数 |
| **卫星 DCB** | 卫星端两频码延迟差（换算到 TEC/距离域后进入 GF） | 全球网可当公共参数估；单站也可用产品改正 |
| **接收机 DCB / IFB** | 接收机端类似的频率相关码延迟差（IFB = Inter-Frequency Bias，常与接收机 DCB 混称） | 换机、换固件、换天线后可能跳变 |
| **绝对 TEC** | 带物理零点意义的 TEC 数值（例如「此刻 42 TECU」） | 对 DCB / 基准极敏感 |
| **相对 TEC / 扰动 TEC** | 相对某参考时段、或差分掉慢变后的变化量 | 常数 DCB 常可近似忽略 |
| **OSB / UPD** | Observable-Specific Bias / Uncalibrated Phase Delay：更细的码/相位偏差产品 | PPP、多系统场景更常见；科学 TEC 课上先抓住 DCB 即可 |
| **IONEX / GIM** | 全球/区域电离层图交换格式与产品；分析中心常**同时**估 TEC 与 DCB | 不同中心绝对水平可差数 TECU |
| **码类型（RINEX）** | 如 C1C、C1W、C2W…：不同跟踪通道/相关器定义 | DCB 产品必须和你用的码对对齐 |

把表读两遍。后面所有「平移」「基准」「相对 vs 绝对」都建立在这些定义上。

## 2. 核心类比：橡皮尺（rubber-ruler）

想象你要量「雾的厚度」（电离层电子含量）。你有一把双频尺：

- 尺身本身可以很好地消掉「你站的位置到卫星的几何距离」——这就是几何无关组合的功劳；
- 但尺子**两端**（卫星端、接收机端）各粘了一小段不知道多长的**橡皮泥**；
- 橡皮泥长度几乎不随「雾厚」变化，短时段内也几乎不随时间扭动。

于是：

1. 你测到的「雾厚」= 真雾厚 + 两端橡皮泥之和（再加噪声）；  
2. 雾一天之内从薄变厚再变薄，曲线形状还在，但**整条曲线被垫高或垫低**；  
3. 若你只关心「今天下午比上午厚了多少」，两端橡皮泥相减后抵消——相对变化仍可用；  
4. 若你要报「现在是 45 TECU」并和 IRI、别的分析中心、别的接收机比绝对值，就必须量出橡皮泥，或大家约定同一把「零点尺」。

**这段两端的橡皮泥，就是 DCB（及同类硬件延迟差）在课堂里的形象。**

再补一个类比：相位几何无关组合像「更干净的游标」，但锁住的是**相对刻度**——每段连续弧有一个未知常数（模糊度），周跳会换一段新常数。伪距给绝对感，相位给平滑感；两者钉在一起时，DCB 与模糊度会抢「谁吸收常数」的锅。

## 3. 几何无关组合里，偏差到底藏在哪

回顾伪距几何无关组合的教学写法（符号因文献略有出入，直觉不变）：

\[
P_{GF} = P_1 - P_2 \propto \mathrm{STEC} + b^{\mathrm{sat}} + b_{\mathrm{rcv}} + \varepsilon
\]

- \(P_1,P_2\)：两个频率上的伪距；  
- \(b^{\mathrm{sat}}\)：卫星端贡献（与卫星 DCB 对应，单位需统一到米或 TECU）；  
- \(b_{\mathrm{rcv}}\)：接收机端贡献；  
- \(\varepsilon\)：噪声、多路径、未模型化项。

相位组合更平滑，但多一个**弧段常数**；周跳或失锁会让常数换一段，看起来像 TEC「台阶」——那不是电离层瞬间塌了，是尺子换了零点。

### 3.1 卫星 DCB vs 接收机 DCB：谁更「公共」？

| | 卫星 DCB | 接收机 DCB / IFB |
|---|---|---|
| 物理位置 | 卫星载荷/天线链路两端频延迟差 | 接收机前端、相关器、固件链路 |
| 网解时角色 | 对全球站网近似**公共**；一颗星一个（或按码对） | 每台接收机一个；站网越大越能与卫星端分离 |
| 单站用户 | 优先用公开产品改正 | 常作为未知数与映射/VTEC 一起估，或与参考站差分削弱 |
| 典型「出事」信号 | 换用错误分析中心产品、码对不匹配 | 换机后 TEC 整天平行跳一截；两机同站差常数 |

课堂口诀：**卫星 DCB 像「天上那把尺的出厂公差」；接收机 DCB 像「你手里这把尺的出厂公差」。两把尺的公差都会进读数。**

### 3.2 为什么绝对 TEC 会「整段平移」？

因为在短时段（数小时到一两天）内，\(b^{\mathrm{sat}}+b_{\mathrm{rcv}}\) 近似常数。常数进不了「形状」，只进「零点」。于是：

- 日变化形态、TID 波纹、磁暴抬升的**相对幅度**往往仍有用；  
- 「今天中午 45 TECU」这种**绝对数字**会跟着常数走；  
- 把未改正的 STEC 拿去和 IGS GIM、IRI 比绝对值，等于拿两把没对齐零点的尺比长度。

### 3.3 相对 vs 绝对：一张决策表

| 你的科学/工程目标 | DCB 要多较真？ | 理由 |
|---|---|---|
| ROTI、相位抖动、扰动检测 | 通常低 | 差分/高通后常数几乎消失 |
| 差分 TEC、相对增强百分比 | 中低 | 注意：若用映射后的 VTEC 再比，映射误差仍在 |
| 单站绝对 VTEC 气候学 | 高 | 零点直接进气候均值 |
| 多站融合建 GIM | 高 | 偏差会泄漏进图与梯度 |
| 与 IRI / 掩星积分比绝对值 | 高 | 否则「模式偏差」其实是尺子偏差 |
| PPP 无电离层组合定位 | 另一条路 | 见第 6 节；不是把 DCB 估成 TEC |

## 4. 和 IGS / 分析中心产品怎么「握手」

### 4.1 为什么 GIM / IONEX 里也有 DCB？

IGS 电离层工作组及相关分析中心做全球 GIM 时，观测方程里同时有：

- 空间部分：格网或球谐等表示的 VTEC（或等价参数）；  
- 偏差部分：一批卫星 DCB、一批接收机 DCB。

地图和偏差是**耦合解**出来的。必须施加基准约束，例如：某组卫星 DCB 之和为 0，或固定某接收机——否则「整网平移」不可观。

因此：

1. 你下载的 IONEX 头文件、伴随 DCB 文件、或分析中心说明里，常能看到偏差相关信息；  
2. 不同中心（如 CODE、JPL、CAS、UPC、WHU、GFZ 等路线）的绝对 TEC 可以差数 TECU——部分来自**基准、观测选择、映射与约束策略**，不全是「谁家电离层更真」；  
3. 比对两家 GIM：先看形态与梯度、地方时结构，再抠绝对水平；组合产品思路可参考 `UWM-IGS-Iono-Combination`。

### 4.3 对齐产品时必问的四个问题

1. **码对**：产品对应 C1W/C2W 还是 C1C/C2W？你的 RINEX 观测量类型是什么？  
2. **单位**：ns、米，还是已换算的 TECU？符号约定（\(P_1-P_2\) 还是反过来）？  
3. **基准**：哪个卫星集合被约束？能否与你的接收机估计同基准相加？  
4. **时间**：日解、快速、实时？换代日是否有跳变？

四个问题答不上，就不要把「和 CODE 差 6 TECU」写成「我的算法烂」。

## 5. 教学版处理流程（五步，每步说清失败模式）

### 步骤 A：选观测量

- **伪距 GF**：无模糊度、有绝对感，但噪声与多路径大。  
- **相位 GF**：平滑，但有弧段常数。  
- **实务**：相位平滑伪距，或「相位相对 + 伪距钉绝对」。

失败模式：只用伪距却期望像文献里一样光滑；或只用相位却拿绝对 TECU 去和 GIM 比。

### 步骤 B：连弧与周跳

相位跳了 → TEC 出台阶。先探测/修复周跳，或分段估常数。

失败模式：把周跳台阶解释成「突发空间天气」。

### 步骤 C：估 / 改正偏差

- 卫星端：优先用公开 DCB/OSB 类产品改正（入口见上表与 `Gkit-Bias`）。  
- 接收机端：单站常当未知数；多站网可把卫星 DCB 当公共参数。  
- TEC 主线工具（估 STEC）：`gnss-tec`、`pygnss-tec`、`tec-suite`、`Seemala-GPS-TEC`、`Okoh-MATLAB-TEC-from-RINEX`、`IONOLAB-TEC-Software`。

失败模式：混用不同分析中心的卫星 DCB，却把自己的接收机 DCB 钉在另一套基准上。

### 步骤 D：对齐产品基准

和 CODE/CAS/JPL/WHU 等比时，统一码对、单位、符号、约束。读 IONEX 可用 `ionex`、`ionex-rs`、`ionex_reader`、`ionex-analyzer`。

### 步骤 E：按目标决定较真程度

回到第 3.3 节决策表。写报告时显式声明：「本结果为相对 TEC」或「绝对 TEC，DCB 来源为××」。

## 6. 和定位的关系（别和 06 打架）

[06-iono-positioning.md](./06-iono-positioning.md) 里，PPP 常用**无电离层组合（IF）**：本质是绕开一阶电离层，不是把 DCB 估成科学 TEC。  
目标是「电子含量科学」→ TEC/GIM 路线；目标是「位置」→ IF/双频消电离层往往更直接。

| 目标 | 典型思路 | 目录可对号 |
|---|---|---|
| 科学 TEC / GIM | 显式估/改正 DCB，输出 STEC/VTEC | `gnss-tec`、`ionex`、`SH-GIM`、`mosgim`、`mosgim2`、`m_gim`、`M_GIM` |
| 精密定位 | IF 组合，或估计电离层参数辅助模糊度 | `RTKLIB`、`gLAB`、`GAMPII-GOOD`、`PRIDE-PPPAR`、`PPP-RTK-Ionosphere` |

两条路都碰偏差，但参数名字与约束习惯不同——写论文时不要把「PPP 的 OSB」和「GIM 的卫星 DCB」混成同一个故事。

## 7. 常见误区（请逐条打假）

1. **「我已经双频了，所以没有偏差」**  
   双频消的是几何与对流层等公共项，**不是**频率相关硬件延迟差。

2. **「DCB 会随 TEC 日变化扭来扭去」**  
   短时段内更像慢变/常数。若你的「DCB」跟着地方时剧烈扭，多半是映射、多路径或弧段断裂被误吸收。

3. **「所有码类型共用同一套 DCB」**  
   C1C、C1W、C2W… 定义不同。RINEX 类型必须和偏差产品对齐。

4. **「两机同站差 5 TECU 且平行 = 电离层真差 5」**  
   优先怀疑接收机 DCB/IFB 或码类型。

5. **「换固件后 TEC 跳了 = 空间天气」**  
   先查硬件延迟是否变了。

6. **「伪距 TEC 与相位 TEC 绝对水平可直接比」**  
   没处理模糊度/平滑策略时，比的是两套零点。

7. **「和某家 GIM 差 8 TECU 就是我错了」**  
   先查基准与时间对齐；中心之间本身有差（见 `UWM-IGS-Iono-Combination` 一类工作）。

8. **「低高度角 DCB 不稳定 = 硬件坏了」**  
   多半是映射与多路径，别全推给硬件。

## 9. 测验（建议闭卷写 15 分钟）

**Q1.** 用橡皮尺类比，说明为什么相对 TEC 对常数 DCB 不敏感，而绝对 TEC 敏感。（约 80 字）

**Q2.** 卫星 DCB 与接收机 DCB 在「全球网解」和「单站解」中的处理策略有何不同？

**Q3.** 两台接收机同一测站、同一时段，STEC 差约 5 TECU 且几乎整天平行。更可能原因是什么？列出至少两个验证步骤。

**Q4.** 你只关心磁暴期间 TEC **相对**增强。DCB 估不准何时仍会致命？

**Q5.** RINEX 用 C1C/C2W，却套了另一对码的 DCB 产品，后果是什么？

**Q6.** 指出本仓库中：两个用于 RINEX→STEC 的条目、两个用于读 IONEX 的条目、两个 IONEX/GIM 数据入口。（必须写 `PROJECTS.json` 中的精确 `name`）

**参考要点（自查，勿死记）：**  
Q1：常数加在两端，差分掉。Q2：卫星端公共/产品改正；接收机端站相关未知数。Q3：接收机 DCB/码类型；换机对比、码类型检查、与公开卫星 DCB 产品对齐后再比。Q4：若相对是对错误映射后的 VTEC、或跨站融合前未统一基准。Q5：系统零点错误。Q6：例如 `gnss-tec`/`Seemala-GPS-TEC`；`ionex`/`ionex-analyzer`；`CDDIS-IONEX`/`JPL-IONEX-Rapid`（答案不唯一，名称必须真实存在）。

## 12. 单位换算直觉（怕公式的人也可以读）

课堂里常把 DCB 说成「几纳秒」。电离层延迟与 TEC 近似成正比，双频组合里「1 ns 量级的差分延迟」可以换算成数 TECU 量级的等效偏差（精确系数取决于频率对，GPS L1/L2 与 BDS/Galileo 不同）。你不必在本课背公式，但必须建立数量级直觉：

- **差 1～3 TECU**：在安静中纬日变化里可能只是「零点争议」；在低纬白天高 TEC 背景下，相对比例更小，但仍足以毁掉「与 IRI 绝对值比对」的结论。  
- **差 5～10 TECU**：两机同站平行差这么多，几乎肯定先查接收机端与码类型，而不是先写「局部电离层异常」。  
- **符号反了**：有人把 \(P_1-P_2\) 与产品定义反号，结果「改正」变成「加倍」——曲线形状仍像，零点更歪。

练习：把你软件输出的 STEC 单位（TECU 还是米？）写在笔记本第一行；再把所用 DCB 产品的单位写在第二行；第三行写换算是否在软件内完成。三行对不齐，就不要开始画「科学结论图」。

## 13. 「相对」也有陷阱：四种看起来像相对、其实仍怕 DCB 的情况

1. **跨站差分但未统一卫星 DCB 产品版本**  
   两站各自改正了不同代的卫星 DCB，差分后残留系统差。

2. **先映射成 VTEC 再做「相对」**  
   高度角、壳高、梯度会把误差变成非常数；你以为减掉了零点，其实减掉的是「错误零点 + 错误映射」。

3. **把不同弧段的相位常数当「相对物理」**  
   弧段拼接不好，相对变化里会出现假台阶。

4. **用一家 GIM 做参考，再宣称自己的「相对偏差」**  
   参考本身含其 DCB 基准；你在测「我与他的差」，不是「我与真理的差」。

所以：口说「我做相对」时，请补半句——**相对的是什么参考、在哪一处理域（STEC 还是 VTEC）差分。**

## PRINCIPLES · DCB 与绝对 / 相对 TEC 原则深讲（必读）

> 本节是第 09 讲的**原则层加长**：把「几何无关组合为何仍剩硬件延迟」「卫星 vs 接收机 DCB」「绝对 vs 相对与基准约束（某 DCB=0）」「IGS DCB/GIM 如何耦合」「未校准 DCB 造成 5 TECU 平移的数值例」「何时相对够用、何时必须绝对」一次讲透。前文是地图；这里是法庭质证材料。文中反引号项目名均来自 [`PROJECTS.json`](../../PROJECTS.json) 的 `name`。

### P1. 课堂谜题升级版：形状对、零点歪

你和同学用同一天 RINEX、相似流程估 STEC，曲线白天高夜里低「长得像」，但竖直方向差了一截几乎平行的常数——常见 3～10 TECU。第一反应别先怪电离层「真的差一截」。原则层优先假设：**尺子两端的橡皮泥（DCB）没对齐**。形状像 → 相对物理可能还在；零点歪 → 绝对值不能拿去和 IRI / 他家 GIM / 另一台接收机硬比。

### P2. 几何无关组合（GF）消了什么、故意没消什么？

双频伪距教学写法（符号随文献略异，直觉不变）：

\[
P_{\mathrm{GF}} = P_1 - P_2 \propto \mathrm{STEC} + b^{\mathrm{sat}} + b_{\mathrm{rcv}} + \varepsilon
\]

| 符号 | 含义 |
|---|---|
| \(P_1,P_2\) | 两频率伪距 |
| \(\mathrm{STEC}\) | 斜路径总电子含量（你想要的科学量） |
| \(b^{\mathrm{sat}}\) | **卫星端**频率相关码延迟差贡献（卫星 DCB 换到组合域） |
| \(b_{\mathrm{rcv}}\) | **接收机端**同类贡献（接收机 DCB / IFB） |
| \(\varepsilon\) | 噪声、多路径、未模型化项 |

GF 擅长消掉：**几何距离、钟差中与频率无关的公共部分、对流层（一阶近似下）** 等「两频相同」的东西。  
GF **消不掉**：**两频硬件延迟之差**——因为延迟本来就随频率/通道不同，相减后变成「差模常数」（短时段内近似常数）。

**原则句（背下来）：** 「几何无关」≠「无偏差」。无关的是几何，不是硬件。

相位 GF 更平滑，但多一个**弧段常数**（模糊度）；周跳换新常数，TEC 出台阶——那是尺子换零点，不是电离层塌了。

### P3. 卫星 DCB vs 接收机 DCB：两块橡皮泥

| | 卫星 DCB | 接收机 DCB / IFB |
|---|---|---|
| 物理位置 | 卫星载荷 / 天线链路两频延迟差 | 接收机前端、相关器、固件 |
| 网解角色 | 对全球站网近似**公共**；一星一参（按码对） | **每站每机**一个；网越大越能与卫星端分离 |
| 单站用户 | 优先用公开产品改正 | 常当未知数与 VTEC/映射同估，或与参考站差分削弱 |
| 典型翻车 | 码对与产品不匹配；混用分析中心基准 | 换机/换固件后整天平行跳；两机同站差常数 |

口诀：**天上尺的出厂公差 + 手里尺的出厂公差 = 读数零点。** 两块泥都要记账。

码类型（RINEX：C1C、C1W、C2W…）不同 → DCB 产品必须与观测量类型对齐。`Gkit-Bias`、`MCOSB` 等偏差工具线索用前读 README；TEC 主线仍是 `gnss-tec`、`pygnss-tec`、`tec-suite`、`Seemala-GPS-TEC`、`Okoh-MATLAB-TEC-from-RINEX`、`IONOLAB-TEC-Software`。

### P4. 绝对 TEC vs 相对 TEC：决策不是口味，是可观性

| 概念 | 定义 | 对常数 DCB |
|---|---|---|
| **绝对 TEC** | 带物理零点的数值（「此刻 42 TECU」） | **极敏感** |
| **相对 TEC / 扰动 TEC** | 相对参考时段、或高通/差分后的变化 | 常数项常可近似消掉 |

橡皮尺：只问「下午比上午厚多少」→ 两端泥相减抵消；要报「现在 45 TECU」并和 IRI 比 → 必须量泥或共用零点尺。

### P5. 基准约束（datum）：「令某个 DCB=0」到底在干什么？

观测方程里，STEC 场与全套 \(b^{\mathrm{sat}}, b_{\mathrm{rcv}}\) 之间存在**整网平移不可观**：把所有卫星 DCB 加常数 \(c\)、所有接收机 DCB 减 \(c\)（符号随参数化约定），组合观测可变得几乎一样，而「绝对 TEC」被重新分配。

因此 IGS 分析中心与自建网解必须施加**基准约束（datum constraint）**，例如：

- 令某颗或某组卫星 DCB 之和为 0；或  
- 固定某台参考接收机 DCB = 0；或  
- 其他可文档化的线性约束。

**「DCB=0」不是物理学声称该硬件零延迟**，而是说：**我们把尺子的零刻度钉在这里**，好让其余参数可估。换约束 = 换零点尺 = 绝对 TEC 可整体跳一截，而相对结构往往仍在。

课堂比喻：全班身高测量，不规定「以谁的鞋底为零」，只规定「差值」，你报不出「绝对海拔」；规定「以讲台地板为零」后，每个人才有绝对读数——地板并不是地球质心。

### P6. IGS DCB 与 GIM 如何耦合（不是两份无关附件）

分析中心做 GIM / IONEX 时，方程里同时有：

1. **空间部分：** 格网或球谐等表示的 VTEC（或等价）；  
2. **偏差部分：** 一批卫星 DCB + 一批接收机 DCB。

二者是**耦合解**：DCB 估歪，会泄漏进地图低阶项或站区系统偏差；地图约束假，也会反灌进 DCB。读产品时记住：

- IONEX 头 / 伴随 DCB 文件 / 分析中心说明里常有偏差信息；  
- 不同中心（CODE、JPL、CAS、UPC、WHU、GFZ 等路线）绝对水平可差数 TECU——来自基准、观测选择、映射与约束，不全是「谁家电离层更真」；  
- 组合与差异语境见 `UWM-IGS-Iono-Combination`、`IGS-Ionosphere-WG`。

数据入口举例：`CDDIS-IONEX`、`JPL-IONEX-Rapid`、`ROB-IONEX-Products`、`ROB-European-TEC`、`GFZ-Global-Ionosphere-Maps`、`WHU-IGS-Ionosphere-AC`、`IGS-Products`、`IGS-Data-Access`、`DLR-IMPC`、`ESA-TIO-NRT-TEC`、`NOAA-SWPC-GloTEC`、`CODE-AIUB-Product-Download`。读图：`ionex`、`ionex-rs`、`ionex_reader`、`ionex-analyzer`、`ionex-downloader`。

#### 对齐产品四问（原则层强制）

1. **码对**是否一致？  
2. **单位**（ns / m / TECU）与符号（\(P_1-P_2\) 方向）？  
3. **基准**约束是什么？能否与你的接收机估计同基准相加？  
4. **时间**（最终/快速/实时）与换代日跳变？

四问不清，禁止把「与 CODE 差 6 TECU」写成「我的算法烂」。


### P7. 数值例：未校准 DCB 造成约 5 TECU 整段平移

下面给一个**教学用假数**（非某日实测），帮助建立数量级与报告句式。

#### 设定

- 真值斜 TEC：某静止时段 \(\mathrm{STEC}_{\mathrm{true}} = 20\,\mathrm{TECU}\)（为便于心算；真实会随时间变）。  
- 卫星+接收机未改正差分延迟，换到 TEC 域后之和：  
  \[
  b^{\mathrm{sat}}+b_{\mathrm{rcv}} = +5\,\mathrm{TECU}
  \]
  （符号：使伪距 GF 估出的 TEC **偏高** 5 TECU。）  
- 噪声暂忽略。

#### 观测

\[
\mathrm{STEC}_{\mathrm{obs}} = \mathrm{STEC}_{\mathrm{true}} + 5 = 25\,\mathrm{TECU}
\]

整天若 \(b^{\mathrm{sat}}+b_{\mathrm{rcv}}\) 近似常数，则整条曲线被**垫高 5 TECU**：白天峰、夜里谷形状仍在，只是零点抬了。

#### 三种后果

| 你的用法 | 后果 |
|---|---|
| 算下午相对上午的增量 \(\Delta\mathrm{STEC}\) | 常数抵消，**相对变化仍可用** |
| 报「此刻绝对 25 TECU」并与 IRI 比 | 你比真值高 5 TECU，**假模式偏差** |
| 两机同站，机 A 改正对、机 B 多 +5 TECU 未改正 | 平行差约 5 TECU，**先查接收机 DCB/码类型**，别写局部电离层异常 |

#### 若符号反了（改正变成加倍）

本应减 5，你加了 5 → 观测变成 \(20+5+5=30\)：形状仍像，零点更歪。原则：**先核对产品符号与 \(P_1-P_2\) 定义，再谈科学。**

#### 纳秒量级直觉（不背系数也要有数感）

DCB 常以 ns 发布；经频率因子换到 TECU 后，**数纳秒**可对应**数 TECU**（精确系数依频率对：GPS L1/L2 与 BDS/Galileo 不同）。课堂记忆：

- 1～3 TECU：安静中纬可能像「零点争议」；仍足以毁掉与 IRI 的绝对值论文结论。  
- 5～10 TECU：两机同站平行差 → 几乎先查硬件/码类型。  
- 练习：笔记本三行——软件 STEC 单位｜DCB 产品单位｜换算是否在软件内完成——对不齐不开画「结论图」。

#### 把 5 TECU 写进方法节的合格句

> 未施加与分析中心同基准的 DCB 改正时，单站伪距 GF STEC 可出现数 TECU 量级的近常数偏移；本工作在相对分析中差分掉该偏移，绝对水平则对齐 `CDDIS-IONEX` 所附 / 伴随 DCB 产品（码对 …，单位 …）。

### P8. 何时相对分析 OK？何时必须绝对？

| 目标 | DCB 较真度 | 理由 |
|---|---|---|
| ROTI、相位抖动、扰动检测 | 低 | 差分/高通后常数近消 |
| 磁暴相对增强百分比（对安静时段） | 中低 | 声明参考时段；注意映射域 |
| 差分 TEC、行扰 δTEC | 中低 | STEC 域相对通常更干净 |
| 单站绝对 VTEC 气候学 | **高** | 零点进气候均值 |
| 多站融合建 GIM | **高** | 偏差泄漏进图与假梯度 |
| 与 IRI / 掩星积分比绝对值 | **高** | 否则「模式差」是尺子差 |
| 跨分析中心拼绝对气候 | **高** | 先统一基准或只比相对场 |
| PPP 无电离层组合定位 | 另一条路 | 见第 06 讲；不是把 DCB 估成科学 TEC |

#### 「相对」也怕 DCB 的四种陷阱

1. 跨站改正了**不同版本**卫星 DCB → 差分残留系统差。  
2. 先映射成 VTEC 再「相对」→ 高度角/壳高把误差变成非常数。  
3. 弧段常数拼接假台阶 → 假相对物理。  
4. 以一家 GIM 为参考谈「我的相对偏差」→ 测的是「我与他」，不是「我与真理」。

口说相对，必补半句：**相对的是什么参考、在 STEC 还是 VTEC 域。**


### P9. 从方程看「为什么加约束才能解」

把单历元、单星简化成：

\[
y = \mathrm{STEC} + b^{s} + b_{r}
\]

多星多站组成方程组后，向量 \(\mathbf{b}^{s}\) 与 \(\mathbf{b}_{r}\) 仍有一维（或若干）零空间：存在非零 \(\boldsymbol{\delta}\) 使观测量不变而参数变。施加例如 \(b_{r_0}=0\) 或 \(\sum_s b^{s}=0\)，等于切开零空间，令最小二乘有唯一解。  

**原则：** 你看到的「卫星 DCB 产品数值」是**在某约束下的数值**；换约束就换数，但兼容的「卫星+接收机」组合应给出同一类 STEC（在忽略其他误差时）。把 A 中心卫星 DCB 接到 B 中心接收机基准上，是经典零点事故。

### P12. 常见误区原则层打假（加长）

1. 「双频了所以无偏差」→ 双频消公共项，不消差模硬件延迟。  
2. 「DCB 跟地方时扭」→ 短时更像常数；剧扭优先查映射/多路径/断弧。  
3. 「所有码共用一套 DCB」→ 否。  
4. 「同站差 5 TECU 平行=电离层真差」→ 先查接收机 DCB。  
5. 「换固件 TEC 跳=空间天气」→ 先查硬件延迟。  
6. 「伪距 TEC 与相位 TEC 绝对水平直接比」→ 零点不同。  
7. 「与某 GIM 差 8 TECU=我错」→ 先查基准；中心之间本有差。  
8. 「低高度角 DCB 不稳=硬件坏」→ 多半映射与多路径。  
9. 「令 DCB=0 表示该星无延迟」→ 只是基准钉，不是物理零。  
10. 「相对分析永远不需要 DCB」→ 见 P8 四种陷阱。


### P13. 工作数值例扩写：从 5 TECU 到「气候学事故」

假设你做夏季中午气候平均 VTEC，真值多年平均 30 TECU。未校准使你的站网整体 +5 TECU。于是：

- 你发表「本区夏季中午 35 TECU」；  
- 与 IRI 比，你写「模式偏低 5 TECU」；  
- 审稿人用另一中心 GIM，发现你与 GIM 也差约 5 TECU 且空间型态很像——  
- 真相：尺子零点，不是模式崩了。

相对课题（暴时增强 20%）若在 STEC 域对安静日差分，5 TECU 常数可消；若先在错误壳高映射到 VTEC 再比，残余可变成「假相对」。**同一 5 TECU，相对课题可能无事，绝对课题足以撤回结论。**

### P14. 同站双机实验（纸上就能做）

机 A、机 B 共天线或极近基线。理想情况差分 STEC 主要剩：\(\Delta b_{\mathrm{rcv}}\)（及噪声/多路径差）。若全天平行差 ≈ 5 TECU：

1. 查码类型是否一致；  
2. 查固件/天线类型；  
3. 用同一套卫星 DCB 产品改正后再比；

### P27. 更深一层：伪距钉绝对、相位保平滑——常数抢锅

实务常用「相位平滑伪距」或「相位相对 + 伪距钉绝对」。原则层要看见三只抢常数的手：

1. **卫星 DCB**；  
2. **接收机 DCB**；  
3. **相位弧段模糊度常数**。

若模型把本该由 DCB 吸收的常数塞进模糊度，或反过来，绝对水平会在弧段边界跳。周跳修复质量差时，看起来像「DCB 在一天内剧变」——多半是弧段记账混乱，不是硬件在呼吸。

检查清单：

- 每段连续弧是否单独估了常数？  
- 伪距权重是否低到「钉不住」绝对？  
- 换用公开卫星 DCB 后，接收机端日估值是否更稳？

工具上仍走 `gnss-tec` / `Seemala-GPS-TEC` / `tec-suite` 等；偏差产品侧参考 `Gkit-Bias`、`MCOSB` 与 IGS 伴随说明。

### P28. 映射函数与 DCB：为何低高度角特别脏

薄壳映射把 STEC 收成 VTEC：\(\mathrm{VTEC}\approx\mathrm{STEC}\cdot\cos z\) 一类（具体形式随模型）。低高度角时：

- 映射误差放大；  
- 多路径更脏；  
- 若把这些系统误差塞进「接收机 DCB 日解」，会出现高度角相关的假变化。

原则：**估 DCB 时用足够高度角门限；报告门限；低高度角数据用于相对形态时要额外 QC。** 「低高度角 DCB 不稳」优先查映射与多路径，而不是先报修接收机。

### P29. 多系统、多码对：原则是「一对手一偏差」

GPS L1/L2、L1/L5，Galileo、BDS 各有通道定义。把 GPS C1W/C2W 的 DCB 套到 BDS 观测量上，是零点灾难。现代 RINEX 字段繁多，原则：

| 检查 | 动作 |
|---|---|
| 观测量类型 | 从 RINEX 头/观测码列核实 |
| 产品类型 | 与 DCB/OSB 产品说明逐字对齐 |
| 系统 | 分系统估或分系统改正 |
| 缺失 | 某码对无产品 → 勿硬套邻码 |

`MCOSB` 一类条目提醒：OSB 比「单一 DCB」更细；科学 TEC 入门仍先抓住 DCB，但多系统论文必须升级到码类型意识。

### P30. 快速 vs 最终产品：时间轴上的零点跳

快速 IONEX（如 `JPL-IONEX-Rapid`）与最终产品策略、站网、约束可能不同，绝对水平可跳。业务流（`DLR-IMPC`、`ESA-TIO-NRT-TEC`、`NOAA-SWPC-GloTEC`）更偏监测时效。原则：

- 气候学与论文绝对值 → 优先最终产品并固定中心；  
- 值班监测 → 可用快速/NRT，但声明「非最终基准」；  
- 换代日、中心切换日 → 检查是否有人工跳变。

### P31. 把「5 TECU」嵌进完整一天故事（教学剧本）

1. 08:00 UTC：两机共站，平行差已见 ≈5 TECU。  
2. 检查码类型：一机用了 C1C，一机用了 C1W 相关组合未声明。

### P44. 附录：从 ns 到 TECU 的课堂换算姿势（不替你背系数）

步骤只要求顺序正确：
