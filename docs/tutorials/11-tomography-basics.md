# 11 · 电离层层析：为什么难，但有人仍要做

GIM 多半给出**平面上的 VTEC**（见 [03-gim-ionex.md](./03-gim-ionex.md)、[10-build-gim-workflow.md](./10-build-gim-workflow.md)）。层析想多问一句：电子密度 \(N_e\) 随**高度**怎么变——二维剖面或三维体素。

本讲不教你推完所有矩阵公式，但要让你知道：为什么问题病态、开源为什么少、以及什么时候不该碰层析。

---

## 课堂类比：CT，但角度很差

医院 CT：X 射线从很多角度穿过人体，反演体内密度。GNSS 层析：卫星—接收机的射线穿过电离层，每条射线的积分为 STEC，反演体素（或层）里的电子密度。

关键差别：

1. GNSS 几何很「斜」，仰角很少到天顶以下的「水平穿射」；  
2. 卫星轨道决定了射线方向，不如 CT 转台自由；  
3. 接收机只在地面（或少量空基），**垂直分辨天生不足**。

所以问题比医学 CT **更病态**：同样能「跑出一张很炫的立方体」，却可能没有唯一物理解。

---

## 你要心里有数的五件事

1. **观测是积分**  
   TEC = 路径上 \(N_e\) 的线积分。信息量少于完整三维场；无数种 \(N_e(h)\) 分布可以积出同一个 TEC。

2. **垂直分辨靠先验**  
   常结合测高仪 foF2/hmF2、掩星电子密度、IRI 背景场作约束，否则高度方向容易「糊成一坨」。互补观测见 [07-ionosonde-occultation.md](./07-ionosonde-occultation.md)。

3. **离散化选择会改答案**  
   体素大小、层厚、时间窗口、平滑约束（Tikhonov、总变差等）都会改结果。换网格不等于「验证成功」。

4. **正演与反演要配套**  
   你用的射线轨迹、地球椭球、穿刺/体素穿越算法，必须和生成仿真数据时一致，否则仿真「完美复现」是自欺。

5. **开源参差不齐**  
   真正可复现的层析仓库，比「读 IONEX」少一个数量级。选工具时看：有没有算例数据、论文对照图、许可是否允许你改。

## 最小数学直觉（不堆公式）

把空间分成许多体素，密度向量为 \(\mathbf{x}\)。每条 GNSS 射线给出一个积分观测 \(y_i\)，于是

\[
\mathbf{y} = A\mathbf{x} + \boldsymbol{\varepsilon}
\]

\(A\) 的每一行是「这条射线穿过各体素的长度（或权重）」。\(A\) 通常又胖又病态：很多 \(\mathbf{x}\) 都能几乎拟合 \(\mathbf{y}\)。实务上要加：

- 背景场（IRI 等）作为初值/约束；  
- 空间平滑或层相关；  
- 多源观测（掩星、测高仪）；  
- 时间连续（相邻历元别跳太狠）。

类比：你只知道若干条「路上车流总和」，却想还原每条巷子里有多少车——没有交通规则（先验），解无穷多。

## 建议学习顺序（千万别跳）

1. 会做单站 STEC（[02](./02-gnss-dualfreq-tec.md)、[09](./09-dcb-biases-deep.md)）  
2. 会做区域 VTEC 图（[10](./10-build-gim-workflow.md)）  
3. 读一篇经典 GNSS 层析论文，只抓：网格、约束、验证图  
4. 用合成数据（如 `synthetic_ionospheric_tomography_isl`）复现「已知真值」  
5. 再上真实站网；同时上测高仪/掩星  

跳步最容易：「能跑出立方体，但无物理」。

## 常见误区

- **「三维可视化很炫 = 已经层析成功」** — 先看能否通过合成数据与独立剖面验证。  
- **「体素越细越好」** — 观测不够时，更细只是更自由地拟合噪声。  
- **「和 GIM 积分一致就够了」** — 积分一致只说明柱总量对，高度结构仍可完全错。  
- **「ML 出三维也叫层析」** — 可以是有用的经验映射，但别和基于射线积分的反演混名（见 [12](./12-data-assimilation-intro.md)、[15](./15-from-paper-to-code.md)）。
