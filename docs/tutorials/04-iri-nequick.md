# 04 · IRI / NeQuick / NeQuick-G：模型解决什么问题？

> **课堂定位**：接 03。你已经知道 GIM/IONEX 是「当天（或近实时）由 GNSS 观测建出来的图」。这节课讲另一条完全不同的答案来源：**经验气候模型**——IRI、NeQuick、以及 Galileo 单频用的 NeQuick-G。
>
> **写给谁**：第一次把 IRI 输出当成「真值」、第一次听说 F10.7、第一次在单频接收机里看到 Galileo 电离层改正、以及分不清「气候平均」和「今天实况」的人。

---

## 1. 这节课解决什么问题（生活 / 工程）

### 1.1 三个会真实卡住你的现场

**现场甲：没有双频、没有 GIM 下载权限，领导仍要「给个电离层延迟」。**  
单频消费设备、教学仿真、链路预算，常常只能靠**广播式/经验式模型**。Galileo 单频用户走的就是 NeQuick-G 路线（与 GPS 经典 Klobuchar 是不同家族）。

**现场乙：论文里写「与 IRI 符合良好」，审稿人问：你比的是气候还是天气？**  
IRI 回答的是：「在这种太阳/地磁条件下，平均来说电离层长什么样？」GIM/双频 STEC 回答的是：「这一天、这一网，观测反演长什么样？」把气候当天气，结论会虚胖。

**现场丙：磁暴夜，模型还给出「平静的漂亮廓线」，你的定位残差却炸了。**  
经验模型在强扰动期可以系统性失灵。这不是软件 bug，而是**方法边界**：气候统计外推，不保证捕捉极端事件。

### 1.2 这节课的交付物

学完你应能：

1. 用一句话区分 **IRI**、**NeQuick**、**NeQuick-G**；  
2. 解释「气候态模型」vs「GNSS 实测 / GIM」；  
3. 对人话说明常用输入（时间、纬经高、F10.7 等）在干什么；  
4. 列出何时**不该**用模型当真值；  
5. 说明 Galileo 单频改正与 NeQuick-G 的链接直觉；  
6. 在 `PROJECTS.json` 里点名真实 IRI/NeQuick 相关 `name`，并知道要配齐公共文件/指数。

### 1.3 边界

- 本课**不**教你读 IONEX（回 03）。  
- 本课**不**把 TIE-GCM 等物理数值模式当 IRI（物理 GCM 是另一条重装备路线，目录另有条目）。  
- 本课**不**把闪烁模型当 TEC 气候（见 05/13）。  
- 模型可以很有用；「有用」≠「当天实况真值」。

## 2. 完整词表（每个术语人话定义）

### 2.1 模型家族

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **经验模型** | 从长期观测统计里「总结出的平均长相」 | 由指数与坐标驱动，不是逐分钟同化预报 |
| **气候态（climatology）** | 「这类日子通常怎样」 | 相对「今天实测天气」 |
| **IRI** | 国际参考电离层，给电子密度等参数的「标准肖像」 | International Reference Ionosphere；COSPAR/URSI 参考 |
| **NeQuick** | 便于给出电子密度廓线并积出 TEC 的经验模型族 | ITU 等传播场景常见 |
| **NeQuick2** | 科研/传播常用的 NeQuick 一代实现口径 | 与 Galileo 版输入不必相同 |
| **NeQuick-G** | Galileo **单频电离层改正**采用的 NeQuick 版本 | 输入与 Galileo 广播消息相关 |
| **Klobuchar** | GPS 经典单频电离层改正模型（另一家族） | 八点系数广播；本课对照用 |
| **NTCM-G** | Galileo 相关的另一类经验改正思路 | 与 NeQuick-G 不同算法族；目录有 `ntcmg` |
| **廓线 \(N_e(h)\)** | 电子密度随高度怎么变 | 模型常能给；GNSS TEC 直接给的是柱积分 |
| **TEC（模型）** | 把廓线沿路径或竖直积分得到的柱总量 | 与 GIM TEC 比时要统一几何与口径 |

### 2.2 驱动与坐标

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **世界时 / 地方时** | 模型要知道「几点」与「当地白天还是晚上」 | 时间与经度一起决定太阳天顶几何 |
| **年积日 / 月份** | 季节信息 | 冬夏气候不同 |
| **地理纬经高** | 你在地球哪里、多高 | 输入的基本三维位置 |
| **地磁纬 / 修正磁纬** | 「相对磁极」的位置，比纯地理纬更能抓住电离层结构 | 许多过程按磁纬组织 |
| **F10.7** | 太阳 10.7 cm 射电流量，当太阳活动「体温计」 | 驱动高层电离；有日值/多日平均等用法 |
| **Ap / Kp / Dst 等** | 地磁活动指数家族 | 不同模型选用不同指数；暴期尤其敏感 |
| **太阳天顶角** | 太阳在当地「抬多高」 | 白天电离的重要几何量 |
| **广播电离层参数** | 卫星导航电文里发给单频用户的系数/参数 | Galileo 的 NeQuick-G 参数 ≠ GPS Klobuchar 八点 |

### 2.3 使用场景词

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **单频改正** | 只有一个频率时，用模型猜电离层延迟 | 消不掉的一阶项靠模型减 |
| **双频无电离层** | 两频组合消一阶电离层** | 02 课；不依赖 IRI |
| **背景场** | 同化或扰动研究里「先铺的平均底子」 | 模型常当背景，实测改背景 |
| **对照气候** | 把实测减气候，看「异常」 | 异常 ≠ 模型错；也可能是天气 |
| **失效模式** | 模型最容易错的时候 | 强磁暴、强 ESA、突发 TIDs 等 |

### 2.4 词表纪律

1. **禁止**说「IRI 测到了 TEC」。应说「IRI 给出了气候态估计」。  
2. **禁止**把 NeQuick2 与 NeQuick-G 的输入输出当成可随意互换的同一按钮。  
3. **禁止**在磁暴个例论文里只用模型、不引用实测/GIM，还宣称「表征了该事件」。  
4. **允许**教学演示先跑在线 IRI，但必须口头声明「这是气候肖像」。

## 3. 主讲解：类比、分步骤、「常见误解」专节

### 3.1 先问对问题：你缺的是「实况」还是「可重复的平均」？

| 你真正需要的 | 更合适的工具 |
|---|---|
| 某日某区尽量贴观测的 VTEC 场 | GNSS GIM / 自建 STEC 建图（03） |
| 完整高度廓线且没有测高仪/掩星 | IRI / NeQuick 等（再声明气候属性） |
| 单频接收机可实现的广播改正 | Klobuchar / **NeQuick-G** / 其他广播模型 |
| 教学、算法基准、可重复实验 | 固定版本的 IRI/NeQuick + 固定指数 |
| 磁暴过程机理与强扰动结构 | 慎用纯气候模型；优先实测 + 物理模式/同化 |

类比总纲：

- **GIM** ≈ 今天的「实况分析天气图」；  
- **IRI/NeQuick** ≈ 「该季节、该太阳活动档的平均气候图」；  
- **NeQuick-G** ≈ 「Galileo 发给单频用户的那本随身气候小册子（带当日广播参数微调）」。

### 3.2 IRI：电离层的「百科全书式标准肖像」

IRI（International Reference Ionosphere）由国际社区长期维护，目标是给出电子密度等参数随高度、时间、位置变化的**参考经验描述**。版本常见口头有 IRI-2016、IRI-2020、IRI-2026 等——**写论文必须写版本**。

人话步骤：

1. 你告诉它：何时、何地、多高（或要整条廓线）；  
2. 再提供/让它读取太阳与地磁相关驱动（视实现与开关）；  
3. 它返回：该点的 \(N_e(h)\) 等；你也可积分得到 TEC；  
4. 你拿去：教学画廓线、与实测比「偏了多少」、给射线追踪当背景、给其他模块当默认电离层。

类比：IRI 像《某城市气候志》里的「七月午后平均气温廓线」——对城市规划有用，但不能替代今天下午的实况温度计。

本仓库相关真实 `name` 稍后专表；这里先记：跑 IRI 常常不只要一个 `.for` 文件，还要 **公共系数/指数文件**（如 `IRI-COMMON-FILES`、`IRI-indices`）。

### 3.3 NeQuick：为「路径 TEC / 传播」友好的廓线模型

NeQuick 族同样给电子密度结构，工程上常强调：**沿任意射线积分得到 TEC/延迟**比较方便，因此在电波传播、链路预算、ITU 相关场景出镜率高。

与 IRI 的直觉分工（简化、便于课堂）：

- IRI ≈ 「参考标准肖像、参数丰富、社区对照基准」；  
- NeQuick ≈ 「传播与 TEC 积分友好的经验廓线工具」。

二者都可以积 TEC；不要说「只有 NeQuick 才有 TEC」。差别在实现生态、输入习惯、社区用途与版本政策。

### 3.4 NeQuick-G：绑在 Galileo 单频上的那一版

**NeQuick-G** 不是「再给科研人员一个随便调用的 NeQuick2 别名」。它是 Galileo **开放服务单频电离层改正**采用的模型实现口径：接收机侧用导航电文中的电离层参数 + 链路几何，估计延迟。

课堂必须建立的链接：

1. **双频用户**：可用无电离层组合，不依赖 NeQuick-G。  
2. **Galileo 单频用户**：官方路线是 NeQuick-G（具体电文参数与实现以 Galileo 接口控制文件/OS SIS ICD 等为准）。  
3. **GPS 单频用户**：经典路线常提 Klobuchar（八点系数）——**另一家族**。  
4. 仿真器/接收机开发者：应优先对照官方源码与文档（目录中有 `Galileo-NeQuick-G`、`NeQuickG-ESSR`、`NequickG` 等），不要把科研 NeQuick2 参数硬塞进 Galileo 电文槽位还自称合规。

类比：NeQuick-G 像「手机地图里内置的官方路况估算公式」；NeQuick2 像「气象实验室自己的气候公式」。都叫路况/气候，接口票据不同。

### 3.5 气候 vs 测量：一张对照表钉死

| | 经验模型（IRI/NeQuick） | GNSS 实测 TEC / GIM |
|---|---|---|
| 数据根 | 历史统计 + 指数驱动 | 当天（或近实时）双频等观测 |
| 空间表现 | 平滑的气候结构 | 可含天气尺度扰动（视产品） |
| 典型输出 | \(N_e(h)\)、衍生 TEC | 柱总量 STEC/VTEC 场 |
| 强项 | 可重复、有廓线、无网也能给数 | 贴实况、事件响应 |
| 失效 | 暴期、强不规则、突发结构 | 测站空洞、DCB、映射、平滑 |

### 3.6 输入直觉：时间、位置、F10.7……各自在拧哪颗旋钮？

把模型想成一台老式收音机，旋钮包括：

1. **时间（日期+时刻）**  
   决定季节与地方时。白天与夜晚、冬夏，电子含量基线不同。

2. **纬度**  
   低纬、中纬、高纬过程不同；赤道异常等结构让「纬度」极敏感。

3. **经度**  
   与世界时一起变成地方时；也影响磁地方时结构。

4. **高度**  
   若你只要 TEC，可能积分整柱；若你做 HF 或掩星对照，廓线形状（F2 峰高度/密度）比单 TEC 更要命。

5. **F10.7（及类似太阳指数）**  
   太阳「亮不亮」的常用代理。高太阳活动年，许多地区白天 TEC 基线更高。注意：用哪一天的 F10.7、是否用多日平均，要按模型说明，乱填会系统性抬高/压低。

6. **地磁指数（Ap 等）**  
   告诉模型「地磁吵不吵」。有的模式对暴期有修正开关；即使有，也**不保证**复现某次超级风暴的细节。

7. **Galileo 广播参数（仅 NeQuick-G 路径）**  
   这是「当日电文给我的微调旋钮」，与你在科研脚本里手填 F10.7 的路径不是同一套用户接口。

步骤建议（科研调用 IRI/NeQuick2 时）：

1. 固定模型版本与系数包；  
2. 写清时间与坐标系（地理/地磁）；  
3. 写清指数来源与日期；  
4. 先出一条正午/午夜廓线看峰高是否合理；  
5. 再积分 TEC，并与同日 GIM 比——比的是「气候 vs 实况差多少」，不是「谁错了」。

### 3.7 何时用模型？何时不要用？

**更倾向模型：**

- 单频定位需要广播改正（NeQuick-G / Klobuchar 等）；  
- 教学演示廓线形状、写单元测试需要可重复背景；  
- 需要 \(N_e(h)\) 而你没有测高仪/掩星/非相干散射；  
- 历史极早期或无 GNSS 网覆盖时段，只能给气候背景；  
- 做「实测减气候」的异常分析（模型当气候基线）。

**更倾向实测 / GIM（不要只用模型）：**

- 论文声称表征「某日 TEC 天气」或某次空间天气事件；  
- 评估闪烁/梯度/风暴响应；  
- 同化、高分辨率区域建图、完好性与精密定位残差归因；  
- 任何要把模型输出叫作「观测真值」的场合。

**常见正确组合：**  
用 IRI/NeQuick 作背景或对照，用 GNSS GIM/STEC 作实况近似；**差异本身可以是课题**，但差异不是自动证明「模型垃圾」或「GIM 垃圾」。

### 3.8 专节：常见误解

**误解 1：IRI 比 GIM 更「物理」、所以更真。**  
错。IRI 是经验参考；GIM 是观测反演产品。真假维度不同。物理数值模式（如 TIE-GCM）又是第三条路。

**误解 2：NeQuick-G 就是 NeQuick2 换皮。**  
错。接口、参数、官方用途绑定 Galileo 单频改正；科研 NeQuick2 不能无声明替换。

**误解 3：把 F10.7 填成「随便一个常数」没关系。**  
错。太阳活动旋钮会整体抬升/压低；对比实验必须记录指数。

**误解 4：模型 TEC 与 GIM TEC 差 5～10 TECU 就说明程序写错。**  
不一定。气候 vs 实况、等离子体层口径、映射与壳高、地方时结构，都可能造成数 TECU 级差异。先查对齐，再查 bug。

**误解 5：单频 + NeQuick-G 可以达到双频无电离层的同等水平。**  
错。模型改正是折中；双频消除一阶项是另一量级的故事（仍有高阶与其他误差）。

**误解 6：有了 IRI 就不需要 `IRI-COMMON-FILES` / 指数。**  
错。缺公共文件是初学者最常见的「能编译、一跑就怪/全零/崩」。

**误解 7：在线点选 IRI（如 CCMC 类入口）的结果可以不写版本直接进论文。**  
危险。必须记录模型版本、选项开关、指数与时间。

**误解 8：赤道地区夜间模型很准，因为「晚上简单」。**  
错。低纬夜间结构、等离子体泡等可让气候模型与实况差很远；夜间不等于简单。

### 3.9 Galileo 单频链接：把故事讲完

请在笔记本画三列：

| 用户类型 | 电离层策略直觉 |
|---|---|
| 双频/多频 | 组合消一阶；模型非必须 |
| GPS 单频（经典） | Klobuchar 广播八点等 |
| Galileo 单频 | **NeQuick-G** + 电文参数 |

工程含义：

- 做 Galileo 仿真/接收机：优先官方 `Galileo-NeQuick-G` 一类源码与 ICD；  
- 做科研传播对比：可用 `NeQuick2-ICTP` 等，但比较对象与声明要清楚；  
- 做「模型 vs GIM」论文：统一时间、坐标、是否竖直、是否含上层贡献。

### 3.10 和 03 课 GIM 的接头话术（考试常考）

问：能不能把 IRI 输出写成 IONEX，然后假装是 IGS GIM？  
答：技术上你也许能把格网写成 IONEX 外形（目录甚至有格式化工具），但**产品语义**仍是气候模型场，不是 IGS 分析中心观测建图。文件名和颜色骗不过方法论。

## 4. IRI / NeQuick 的输入输出与文件、调用直觉

### 4.1 IRI（科研包）直觉

| 项目 | 内容 |
|---|---|
| **输入** | 时间、纬、经、高度或高度网格；太阳/地磁指数；选项开关（哪一版算法块等） |
| **依赖文件** | 系数与公共文件、指数序列（`IRI-COMMON-FILES`、`IRI-indices` 等） |
| **输出** | \(N_e(h)\)、相关参数；可积分 TEC |
| **调用直觉** | 「先备齐数据文件，再调用库函数」；不是「pip 装完立刻有全球真相」 |

Python 包装（如 `PyIRI`、`iri2020`、`iri2016`）降低了入口门槛，但**版本与系数一致性**仍要你自己负责。

### 4.2 NeQuick2 直觉

| 项目 | 内容 |
|---|---|
| **输入** | 时间位置、太阳活动代理等（以 ICTP/实现文档为准） |
| **输出** | 廓线与/或链路 TEC |
| **调用直觉** | 传播与积分友好；注意与 Galileo 版分家 |

### 4.3 NeQuick-G 直觉

| 项目 | 内容 |
|---|---|
| **输入** | Galileo 电离层电文参数 + 接收机/卫星几何（方位仰角等） |
| **输出** | 单频用户电离层延迟估计 |
| **调用直觉** | 嵌在导航引擎里的改正模块；对照官方 C 源码与认证/发布说明 |

### 4.4 「不要用模型」的操作化检查单

出现任一情况，暂停把模型当实况真值：

1. 研究目标写着「事件期间 TEC 变化」；  
2. 地磁指数显示强扰动，而你仍只用平静气候默认；  
3. 你需要小尺度梯度/闪烁，而模型只有平滑气候；  
4. 你无法说清指数与版本；  
5. 审稿人问「观测在哪」时你只能指模型图。

## 6. 课堂检查题 + 答案

**题 1**：一句话区分 IRI、NeQuick、NeQuick-G。  
**答**：IRI 是国际参考经验电离层（标准肖像）；NeQuick 是便于廓线/TEC 积分的经验模型族；NeQuick-G 是 Galileo 单频改正采用的 NeQuick 版本，接口绑广播参数。

**题 2**：气候态与实测 GIM 的核心差别？  
**答**：气候态由历史统计+指数驱动给「通常怎样」；GIM 由当天观测建「这一天怎样」。

**题 3**：F10.7 在模型里像什么旋钮？  
**答**：太阳活动强弱的代理「体温计」，影响高层电离基线；乱填会导致整体偏差。

**题 4**：举出三种「不该把模型当真值」的场合。  
**答示例**：磁暴事件表征；小尺度梯度/闪烁研究；论文需要观测实况却只交模型图。

**题 5**：Galileo 单频与 GPS 经典单频改正模型各点名一个。  
**答**：Galileo → NeQuick-G；GPS 经典 → Klobuchar（对照用）。

**题 6**：本仓库给出两个 IRI 包名、一个公共文件名、一个 NeQuick2 名、一个 NeQuick-G 名。  
**答示例**：`IRI-2026-package`、`IRI-2020-package`；`IRI-COMMON-FILES`；`NeQuick2-ICTP`；`Galileo-NeQuick-G`。

**题 7**：为何模型 TEC 与 GIM 差几个 TECU 不一定是代码错误？  
**答**：气候 vs 实况、口径（是否含上层）、几何映射、指数与版本都可造成数 TECU 差；先对齐再查 bug。

**题 8**：把 IRI 格网存成 IONEX 外形，能否在论文里称为 IGS GIM？  
**答**：不能。格式外壳≠ IGS 观测分析中心产品语义。

## 7. 下一节预告

下一讲：[05-scintillation-roti.md](./05-scintillation-roti.md)

TEC/GIM/气候模型讲的是「柱子有多厚、平均长什么样」。下一课进入另一现象：**闪烁与 ROTI**——信号发抖、相位乱跳。你将分清：高 TEC ≠ 一定强闪烁；ROTI 在测什么；以及目录里哪些工具吃的是高频采样而不是 IONEX 日产品。

本课若只带走三句：

1. IRI/NeQuick 是气候经验，GIM/双频是观测实况路线。

3. 磁暴与事件研究，模型最多当对照，不能冒充当天真值。
