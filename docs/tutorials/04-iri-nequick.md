# 04 · IRI / NeQuick / NeQuick-G：模型解决什么问题？

> **课堂定位**：接 03。你已经知道 GIM/IONEX 是「当天（或近实时）由 GNSS 观测建出来的图」。这节课讲另一条完全不同的答案来源：**经验气候模型**——IRI、NeQuick、以及 Galileo 单频用的 NeQuick-G。
>
> **写给谁**：第一次把 IRI 输出当成「真值」、第一次听说 F10.7、第一次在单频接收机里看到 Galileo 电离层改正、以及分不清「气候平均」和「今天实况」的人。

---

## 1. 这节课解决什么问题（生活 / 工程）

### 1.1 三个会真实卡住你的现场

**现场甲：没有双频、没有 GIM 下载权限，领导仍要「给个电离层延迟」。**  
单频消费设备、教学仿真、链路预算，常常只能靠**广播式/经验式模型**。Galileo 单频用户走的就是 NeQuick-G 路线（与 GPS 经典 Klobuchar 是不同家族）。

**现场乙：论文里写「与 IRI 符合良好」，审稿人问：你比的是气候还是天气？**  
IRI 回答的是：「在这种太阳/地磁条件下，平均来说电离层长什么样？」GIM/双频 STEC 回答的是：「这一天、这一网，观测反演长什么样？」把气候当天气，结论会虚胖。

**现场丙：磁暴夜，模型还给出「平静的漂亮廓线」，你的定位残差却炸了。**  
经验模型在强扰动期可以系统性失灵。这不是软件 bug，而是**方法边界**：气候统计外推，不保证捕捉极端事件。

### 1.2 这节课的交付物

学完你应能：

1. 用一句话区分 **IRI**、**NeQuick**、**NeQuick-G**；  
2. 解释「气候态模型」vs「GNSS 实测 / GIM」；  
3. 对人话说明常用输入（时间、纬经高、F10.7 等）在干什么；  
4. 列出何时**不该**用模型当真值；  
5. 说明 Galileo 单频改正与 NeQuick-G 的链接直觉；  
6. 在 `PROJECTS.json` 里点名真实 IRI/NeQuick 相关 `name`，并知道要配齐公共文件/指数。

### 1.3 边界

- 本课**不**教你读 IONEX（回 03）。  
- 本课**不**把 TIE-GCM 等物理数值模式当 IRI（物理 GCM 是另一条重装备路线，目录另有条目）。  
- 本课**不**把闪烁模型当 TEC 气候（见 05/13）。  
- 模型可以很有用；「有用」≠「当天实况真值」。

## 2. 完整词表（每个术语人话定义）

### 2.1 模型家族

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **经验模型** | 从长期观测统计里「总结出的平均长相」 | 由指数与坐标驱动，不是逐分钟同化预报 |
| **气候态（climatology）** | 「这类日子通常怎样」 | 相对「今天实测天气」 |
| **IRI** | 国际参考电离层，给电子密度等参数的「标准肖像」 | International Reference Ionosphere；COSPAR/URSI 参考 |
| **NeQuick** | 便于给出电子密度廓线并积出 TEC 的经验模型族 | ITU 等传播场景常见 |
| **NeQuick2** | 科研/传播常用的 NeQuick 一代实现口径 | 与 Galileo 版输入不必相同 |
| **NeQuick-G** | Galileo **单频电离层改正**采用的 NeQuick 版本 | 输入与 Galileo 广播消息相关 |
| **Klobuchar** | GPS 经典单频电离层改正模型（另一家族） | 八点系数广播；本课对照用 |
| **NTCM-G** | Galileo 相关的另一类经验改正思路 | 与 NeQuick-G 不同算法族；目录有 `ntcmg` |
| **廓线 $N_e(h)$** | 电子密度随高度怎么变 | 模型常能给；GNSS TEC 直接给的是柱积分 |
| **TEC（模型）** | 把廓线沿路径或竖直积分得到的柱总量 | 与 GIM TEC 比时要统一几何与口径 |

### 2.2 驱动与坐标

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **世界时 / 地方时** | 模型要知道「几点」与「当地白天还是晚上」 | 时间与经度一起决定太阳天顶几何 |
| **年积日 / 月份** | 季节信息 | 冬夏气候不同 |
| **地理纬经高** | 你在地球哪里、多高 | 输入的基本三维位置 |
| **地磁纬 / 修正磁纬** | 「相对磁极」的位置，比纯地理纬更能抓住电离层结构 | 许多过程按磁纬组织 |
| **F10.7** | 太阳 10.7 cm 射电流量，当太阳活动「体温计」 | 驱动高层电离；有日值/多日平均等用法 |
| **Ap / Kp / Dst 等** | 地磁活动指数家族 | 不同模型选用不同指数；暴期尤其敏感 |
| **太阳天顶角** | 太阳在当地「抬多高」 | 白天电离的重要几何量 |
| **广播电离层参数** | 卫星导航电文里发给单频用户的系数/参数 | Galileo 的 NeQuick-G 参数 ≠ GPS Klobuchar 八点 |

### 2.3 使用场景词

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **单频改正** | 只有一个频率时，用模型猜电离层延迟 | 消不掉的一阶项靠模型减 |
| **双频无电离层** | 两频组合消一阶电离层** | 02 课；不依赖 IRI |
| **背景场** | 同化或扰动研究里「先铺的平均底子」 | 模型常当背景，实测改背景 |
| **对照气候** | 把实测减气候，看「异常」 | 异常 ≠ 模型错；也可能是天气 |
| **失效模式** | 模型最容易错的时候 | 强磁暴、强 ESA、突发 TIDs 等 |

### 2.4 词表纪律

1. **禁止**说「IRI 测到了 TEC」。应说「IRI 给出了气候态估计」。  
2. **禁止**把 NeQuick2 与 NeQuick-G 的输入输出当成可随意互换的同一按钮。  
3. **禁止**在磁暴个例论文里只用模型、不引用实测/GIM，还宣称「表征了该事件」。  
4. **允许**教学演示先跑在线 IRI，但必须口头声明「这是气候肖像」。

## 3. 主讲解：类比、分步骤、「常见误解」专节

### 3.1 先问对问题：你缺的是「实况」还是「可重复的平均」？

| 你真正需要的 | 更合适的工具 |
|---|---|
| 某日某区尽量贴观测的 VTEC 场 | GNSS GIM / 自建 STEC 建图（03） |
| 完整高度廓线且没有测高仪/掩星 | IRI / NeQuick 等（再声明气候属性） |
| 单频接收机可实现的广播改正 | Klobuchar / **NeQuick-G** / 其他广播模型 |
| 教学、算法基准、可重复实验 | 固定版本的 IRI/NeQuick + 固定指数 |
| 磁暴过程机理与强扰动结构 | 慎用纯气候模型；优先实测 + 物理模式/同化 |

类比总纲：

- **GIM** ≈ 今天的「实况分析天气图」；  
- **IRI/NeQuick** ≈ 「该季节、该太阳活动档的平均气候图」；  
- **NeQuick-G** ≈ 「Galileo 发给单频用户的那本随身气候小册子（带当日广播参数微调）」。

### 3.2 IRI：电离层的「百科全书式标准肖像」

IRI（International Reference Ionosphere）由国际社区长期维护，目标是给出电子密度等参数随高度、时间、位置变化的**参考经验描述**。版本常见口头有 IRI-2016、IRI-2020、IRI-2026 等——**写论文必须写版本**。

人话步骤：

1. 你告诉它：何时、何地、多高（或要整条廓线）；  
2. 再提供/让它读取太阳与地磁相关驱动（视实现与开关）；  
3. 它返回：该点的 $N_e(h)$ 等；你也可积分得到 TEC；  
4. 你拿去：教学画廓线、与实测比「偏了多少」、给射线追踪当背景、给其他模块当默认电离层。

类比：IRI 像《某城市气候志》里的「七月午后平均气温廓线」——对城市规划有用，但不能替代今天下午的实况温度计。

本仓库相关真实 `name` 稍后专表；这里先记：跑 IRI 常常不只要一个 `.for` 文件，还要 **公共系数/指数文件**（如 `IRI-COMMON-FILES`、`IRI-indices`）。

### 3.3 NeQuick：为「路径 TEC / 传播」友好的廓线模型

NeQuick 族同样给电子密度结构，工程上常强调：**沿任意射线积分得到 TEC/延迟**比较方便，因此在电波传播、链路预算、ITU 相关场景出镜率高。

与 IRI 的直觉分工（简化、便于课堂）：

- IRI ≈ 「参考标准肖像、参数丰富、社区对照基准」；  
- NeQuick ≈ 「传播与 TEC 积分友好的经验廓线工具」。

二者都可以积 TEC；不要说「只有 NeQuick 才有 TEC」。差别在实现生态、输入习惯、社区用途与版本政策。

### 3.4 NeQuick-G：绑在 Galileo 单频上的那一版

**NeQuick-G** 不是「再给科研人员一个随便调用的 NeQuick2 别名」。它是 Galileo **开放服务单频电离层改正**采用的模型实现口径：接收机侧用导航电文中的电离层参数 + 链路几何，估计延迟。

课堂必须建立的链接：

1. **双频用户**：可用无电离层组合，不依赖 NeQuick-G。  
2. **Galileo 单频用户**：官方路线是 NeQuick-G（具体电文参数与实现以 Galileo 接口控制文件/OS SIS ICD 等为准）。  
3. **GPS 单频用户**：经典路线常提 Klobuchar（八点系数）——**另一家族**。  
4. 仿真器/接收机开发者：应优先对照官方源码与文档（目录中有 `Galileo-NeQuick-G`、`NeQuickG-ESSR`、`NequickG` 等），不要把科研 NeQuick2 参数硬塞进 Galileo 电文槽位还自称合规。

类比：NeQuick-G 像「手机地图里内置的官方路况估算公式」；NeQuick2 像「气象实验室自己的气候公式」。都叫路况/气候，接口票据不同。

### 3.5 气候 vs 测量：一张对照表钉死

| | 经验模型（IRI/NeQuick） | GNSS 实测 TEC / GIM |
|---|---|---|
| 数据根 | 历史统计 + 指数驱动 | 当天（或近实时）双频等观测 |
| 空间表现 | 平滑的气候结构 | 可含天气尺度扰动（视产品） |
| 典型输出 | $N_e(h)$、衍生 TEC | 柱总量 STEC/VTEC 场 |
| 强项 | 可重复、有廓线、无网也能给数 | 贴实况、事件响应 |
| 失效 | 暴期、强不规则、突发结构 | 测站空洞、DCB、映射、平滑 |

### 3.6 输入直觉：时间、位置、F10.7……各自在拧哪颗旋钮？

把模型想成一台老式收音机，旋钮包括：

1. **时间（日期+时刻）**  
   决定季节与地方时。白天与夜晚、冬夏，电子含量基线不同。

2. **纬度**  
   低纬、中纬、高纬过程不同；赤道异常等结构让「纬度」极敏感。

3. **经度**  
   与世界时一起变成地方时；也影响磁地方时结构。

4. **高度**  
   若你只要 TEC，可能积分整柱；若你做 HF 或掩星对照，廓线形状（F2 峰高度/密度）比单 TEC 更要命。

5. **F10.7（及类似太阳指数）**  
   太阳「亮不亮」的常用代理。高太阳活动年，许多地区白天 TEC 基线更高。注意：用哪一天的 F10.7、是否用多日平均，要按模型说明，乱填会系统性抬高/压低。

6. **地磁指数（Ap 等）**  
   告诉模型「地磁吵不吵」。有的模式对暴期有修正开关；即使有，也**不保证**复现某次超级风暴的细节。

7. **Galileo 广播参数（仅 NeQuick-G 路径）**  
   这是「当日电文给我的微调旋钮」，与你在科研脚本里手填 F10.7 的路径不是同一套用户接口。

步骤建议（科研调用 IRI/NeQuick2 时）：

1. 固定模型版本与系数包；  
2. 写清时间与坐标系（地理/地磁）；  
3. 写清指数来源与日期；  
4. 先出一条正午/午夜廓线看峰高是否合理；  
5. 再积分 TEC，并与同日 GIM 比——比的是「气候 vs 实况差多少」，不是「谁错了」。

### 3.7 何时用模型？何时不要用？

**更倾向模型：**

- 单频定位需要广播改正（NeQuick-G / Klobuchar 等）；  
- 教学演示廓线形状、写单元测试需要可重复背景；  
- 需要 $N_e(h)$ 而你没有测高仪/掩星/非相干散射；  
- 历史极早期或无 GNSS 网覆盖时段，只能给气候背景；  
- 做「实测减气候」的异常分析（模型当气候基线）。

**更倾向实测 / GIM（不要只用模型）：**

- 论文声称表征「某日 TEC 天气」或某次空间天气事件；  
- 评估闪烁/梯度/风暴响应；  
- 同化、高分辨率区域建图、完好性与精密定位残差归因；  
- 任何要把模型输出叫作「观测真值」的场合。

**常见正确组合：**  
用 IRI/NeQuick 作背景或对照，用 GNSS GIM/STEC 作实况近似；**差异本身可以是课题**，但差异不是自动证明「模型垃圾」或「GIM 垃圾」。

### 3.8 专节：常见误解

**误解 1：IRI 比 GIM 更「物理」、所以更真。**  
错。IRI 是经验参考；GIM 是观测反演产品。真假维度不同。物理数值模式（如 TIE-GCM）又是第三条路。

**误解 2：NeQuick-G 就是 NeQuick2 换皮。**  
错。接口、参数、官方用途绑定 Galileo 单频改正；科研 NeQuick2 不能无声明替换。

**误解 3：把 F10.7 填成「随便一个常数」没关系。**  
错。太阳活动旋钮会整体抬升/压低；对比实验必须记录指数。

**误解 4：模型 TEC 与 GIM TEC 差 5～10 TECU 就说明程序写错。**  
不一定。气候 vs 实况、等离子体层口径、映射与壳高、地方时结构，都可能造成数 TECU 级差异。先查对齐，再查 bug。

**误解 5：单频 + NeQuick-G 可以达到双频无电离层的同等水平。**  
错。模型改正是折中；双频消除一阶项是另一量级的故事（仍有高阶与其他误差）。

**误解 6：有了 IRI 就不需要 `IRI-COMMON-FILES` / 指数。**  
错。缺公共文件是初学者最常见的「能编译、一跑就怪/全零/崩」。

**误解 7：在线点选 IRI（如 CCMC 类入口）的结果可以不写版本直接进论文。**  
危险。必须记录模型版本、选项开关、指数与时间。

**误解 8：赤道地区夜间模型很准，因为「晚上简单」。**  
错。低纬夜间结构、等离子体泡等可让气候模型与实况差很远；夜间不等于简单。

### 3.9 Galileo 单频链接：把故事讲完

请在笔记本画三列：

| 用户类型 | 电离层策略直觉 |
|---|---|
| 双频/多频 | 组合消一阶；模型非必须 |
| GPS 单频（经典） | Klobuchar 广播八点等 |
| Galileo 单频 | **NeQuick-G** + 电文参数 |

工程含义：

- 做 Galileo 仿真/接收机：优先官方 `Galileo-NeQuick-G` 一类源码与 ICD；  
- 做科研传播对比：可用 `NeQuick2-ICTP` 等，但比较对象与声明要清楚；  
- 做「模型 vs GIM」论文：统一时间、坐标、是否竖直、是否含上层贡献。

### 3.10 和 03 课 GIM 的接头话术（考试常考）

问：能不能把 IRI 输出写成 IONEX，然后假装是 IGS GIM？  
答：技术上你也许能把格网写成 IONEX 外形（目录甚至有格式化工具），但**产品语义**仍是气候模型场，不是 IGS 分析中心观测建图。文件名和颜色骗不过方法论。

## 4. IRI / NeQuick 的输入输出与文件、调用直觉

### 4.1 IRI（科研包）直觉

| 项目 | 内容 |
|---|---|
| **输入** | 时间、纬、经、高度或高度网格；太阳/地磁指数；选项开关（哪一版算法块等） |
| **依赖文件** | 系数与公共文件、指数序列（`IRI-COMMON-FILES`、`IRI-indices` 等） |
| **输出** | $N_e(h)$、相关参数；可积分 TEC |
| **调用直觉** | 「先备齐数据文件，再调用库函数」；不是「pip 装完立刻有全球真相」 |

Python 包装（如 `PyIRI`、`iri2020`、`iri2016`）降低了入口门槛，但**版本与系数一致性**仍要你自己负责。

### 4.2 NeQuick2 直觉

| 项目 | 内容 |
|---|---|
| **输入** | 时间位置、太阳活动代理等（以 ICTP/实现文档为准） |
| **输出** | 廓线与/或链路 TEC |
| **调用直觉** | 传播与积分友好；注意与 Galileo 版分家 |

### 4.3 NeQuick-G 直觉

| 项目 | 内容 |
|---|---|
| **输入** | Galileo 电离层电文参数 + 接收机/卫星几何（方位仰角等） |
| **输出** | 单频用户电离层延迟估计 |
| **调用直觉** | 嵌在导航引擎里的改正模块；对照官方 C 源码与认证/发布说明 |

### 4.4 「不要用模型」的操作化检查单

出现任一情况，暂停把模型当实况真值：

1. 研究目标写着「事件期间 TEC 变化」；  
2. 地磁指数显示强扰动，而你仍只用平静气候默认；  
3. 你需要小尺度梯度/闪烁，而模型只有平滑气候；  
4. 你无法说清指数与版本；  
5. 审稿人问「观测在哪」时你只能指模型图。

## 6. 课堂检查题 + 答案

**题 1**：一句话区分 IRI、NeQuick、NeQuick-G。  
**答**：IRI 是国际参考经验电离层（标准肖像）；NeQuick 是便于廓线/TEC 积分的经验模型族；NeQuick-G 是 Galileo 单频改正采用的 NeQuick 版本，接口绑广播参数。

**题 2**：气候态与实测 GIM 的核心差别？  
**答**：气候态由历史统计+指数驱动给「通常怎样」；GIM 由当天观测建「这一天怎样」。

**题 3**：F10.7 在模型里像什么旋钮？  
**答**：太阳活动强弱的代理「体温计」，影响高层电离基线；乱填会导致整体偏差。

**题 4**：举出三种「不该把模型当真值」的场合。  
**答示例**：磁暴事件表征；小尺度梯度/闪烁研究；论文需要观测实况却只交模型图。

**题 5**：Galileo 单频与 GPS 经典单频改正模型各点名一个。  
**答**：Galileo → NeQuick-G；GPS 经典 → Klobuchar（对照用）。

**题 6**：本仓库给出两个 IRI 包名、一个公共文件名、一个 NeQuick2 名、一个 NeQuick-G 名。  
**答示例**：`IRI-2026-package`、`IRI-2020-package`；`IRI-COMMON-FILES`；`NeQuick2-ICTP`；`Galileo-NeQuick-G`。

**题 7**：为何模型 TEC 与 GIM 差几个 TECU 不一定是代码错误？  
**答**：气候 vs 实况、口径（是否含上层）、几何映射、指数与版本都可造成数 TECU 差；先对齐再查 bug。

**题 8**：把 IRI 格网存成 IONEX 外形，能否在论文里称为 IGS GIM？  
**答**：不能。格式外壳≠ IGS 观测分析中心产品语义。

## 8. 模型−数据残差：当「现象探测器」还是「模型失灵警报」？

> **本节目标**：学会把 **残差 = 观测（或 GIM）− 模型（IRI/NeQuick）** 当成一种分析语言。残差可以揭示风暴、赤道异常偏离气候、行进式扰动等**物理天气**；也可以只是指数填错、版本不一致、口径不齐、模型在暴期本来就不会的**方法失败**。现象分析心态要求你每次看到大红大蓝的残差图，先开庭审判：「这是地球在说话，还是模型在罢工？」

### 8.1 先补词表：残差分析专用

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **残差（residual）** | 实况减气候（或减模型）剩下的差 | $R = X_{\mathrm{data}} - X_{\mathrm{model}}$ |
| **正残差** | 实况比模型厚 | 可能是正异常天气，也可能是模型系统性偏低 |
| **负残差** | 实况比模型薄 | 同上，符号相反 |
| **物理残差** | 差里主要是真实天气相对气候的偏离 | 应用多源证实 |
| **模型失效残差** | 差里主要是模型超出能力范围或设错旋钮 | 暴期、错指数、错版本常见 |
| **气候基线用法** | 故意用模型当「通常怎样」，让残差当异常指标 | 合法，但须声明 |
| **真值错觉** | 把残差大自动说成「观测错了」或「发现新物理」 | 两种武断都危险 |
| **口径对齐** | 比的都是 VTEC 还是 STEC？含不含上层？壳高？ | 不对齐的残差无资格叫探测器 |

**词表纪律：** 禁止说「IRI 测小了所以我发现了增强」——应说「相对 IRI-某版本气候估计，GIM/STEC 偏高 N TECU；需排除指数与口径后，再解释为天气异常」。

### 8.2 残差法庭：三种判决

把每一次显眼残差送上法庭，只允许三种判决（可并存，但要分开写）：

**判决 α：物理天气（现象成立倾向）**  
证据：残差时间与磁暴/耀斑窗口对齐；空间结构符合已知形貌（正负暴分区、EIA 变形等）；换一家 GIM、换一批质控过的测站，残差同号；模型指数与版本经核对无低级错误。

**判决 β：模型失灵 / 旋钮错误（方法问题）**  
证据：指数日期填错或用了平静默认却声称暴期模拟；NeQuick2 与 NeQuick-G 接口混用；缺 `IRI-COMMON-FILES` / `IRI-indices` 导致怪值；版本未声明；残差随「你改 F10.7」剧烈变，却几乎不随真实指数窗口变。

**判决 γ：口径假残差（苹果减橘子）**  
证据：用 STEC 减竖直模型 TEC；时间未对齐；经度定义相反；GIM 含/不含某上层贡献与模型积分限不同；单频广播改正输出被当成垂直 TEC 真值。

课堂口诀：**先排 γ，再查 β，最后才宣 α。**

### 8.3 详细走查：用残差当探测器（合法流程）

#### 步骤 1：固定「数据侧」是谁

优先顺序建议：

1. 质控后的双频 STEC→映射 VTEC（02 课门禁通过）；  
2. 或某 AC 的 GIM/IONEX（03 课：`CDDIS-IONEX`、`JPL-IONEX-Rapid`、`UPC-IONEX-Archive` 等）；  
3. 近实时产品（`ESA-TIO-NRT-TEC`、`NOAA-SWPC-GloTEC`、`CAS-BDsmart-RTS-Iono`）只作快速看图，精密结论慎用。

#### 步骤 2：固定「模型侧」是谁

1. 写死版本：如 `IRI-2026-package` / `IRI-2020-package` / `iri2020` / `PyIRI`，或 `NeQuick2-ICTP`。  
2. 配齐 `IRI-COMMON-FILES`、`IRI-indices`（IRI 路径）。  
3. 记录 F10.7、Ap 等来源与日期；暴期研究不要偷用气候默认值还假装「驱动了暴」。  
4. Galileo 单频场景用 `Galileo-NeQuick-G` / `NequickG` / `NeQuickG-ESSR`，不要拿科研 NeQuick2 残差解释电文改正性能，除非明确做的就是跨口径对比。

#### 步骤 3：对齐几何与时间

1. 统一到 VTEC 或统一到同一射线 STEC。  
2. 同一世界时（或地方时）切片。  
3. 积分高度范围若可知，尽量声明；不知则当局限写进结论。

#### 步骤 4：算残差并可视化

$$
R(\lambda,\varphi,t)=X_{\mathrm{data}}-X_{\mathrm{model}}
$$

对称色标；同时保留数据绝对场与模型绝对场，避免「只看残差做梦」。  
仓库中 `mgfernan-pygnss`、`gri-iono`、`CCMC-IRI-online` 等可用于对照实验（以各项目文档为准）；差分制图思路可参考 `DiffIonMap`。

#### 步骤 5：开庭（用问题清单代替感觉）

1. 我改对 F10.7 之后，残差是否只发生整体平移？若是，可能是旋钮，不是新物理。  
2. 残差是否在测站稠密区与稀疏区同样「精细」？稀疏区过细 → 降级。  
3. 残差时间演变是否跟着 Dst/Kp，而不是跟着我换模型版本的时间？  
4. 残差空间型是否像文献中的正/负暴，而不是像球谐阶数不足的平滑斑？  
5. 若只用模型、不用数据，我还能讲同一个「事件故事」吗？若能，那故事太可疑——说明你可能在叙述模型自己的气候形状。

### 8.4 何时残差更像物理？何时更像模型失败？

| 线索 | 偏物理残差 | 偏模型失败 / 假残差 |
|---|---|---|
| 时间 | 与主相/恢复相对齐 | 与你改输入文件的时间对齐 |
| 空间 | 分区正负、地方时依赖合理 | 全球均匀偏置或随格网伪纹走 |
| 敏感性 | 换指数合理范围内，结构仍在 | 轻微改 F10.7，结构面目全非或整体滑走 |
| 多源 | GIM、单站、掩星/测高仪同号 | 只有你的一种模型减一种数据在喊 |
| 活动水平 | 中等扰动下结构清晰 | 超级风暴期模型平滑得像没发生 |
| 文档 | 版本指数齐全 | 缺公共文件、混用 NeQuick-G/2 |

**超级风暴特判：** 经验模型在极端期「残差巨大」几乎是预期。巨大残差**证明「气候模型不是事件真值」**，本身很有价值；但若你的论文标题是「基于 IRI 表征了该超级风暴的精细结构」，法庭应直接驳回。正确用法：IRI 作气候基线，GIM/STEC 作实况，残差作「偏离气候的幅度图」。

### 8.5 类比加深：体检化验单

把 IRI/NeQuick 想成「同龄人平均体检表」。  
把 GIM/STEC 想成「你今天的化验单」。  
残差想成「偏高偏低的箭头」。

- 箭头大且与你刚跑完马拉松的时间对齐 → 更像真实生理响应（物理残差）。  
- 化验单用错了单位，或平均表印错了年龄组 → 假箭头（口径/旋钮）。  
- 平均表本来就不是为「高烧病人」设计的 → 发烧时箭头狂跳，说明「别拿平均表当急诊监护仪」（模型失灵边界）。

### 8.6 常见误解专节（残差篇）

**误解 1：残差大 = 我发现了新物理。**  
打假：先排口径与指数；再多源证实。

**误解 2：残差小 = 模型完美、无天气。**  
打假：也可能是数据被平滑、或你比的是两个都偏平滑的场；小残差不自动等于「无现象」。

**误解 3：用 NeQuick-G 残差评价 IRI 论文结论可直接搬家。**  
打假：接口与用途不同；跨模型残差要单独设计实验。

**误解 4：在线点选 `CCMC-IRI-online` 的图减 GIM 就可以不记版本。**  
打假：版本与开关是残差可重复性的生命线。

**误解 5：残差图可以替代 03 课的安静日差值图。**  
不完全。安静日差值是「实况−实况」；模型残差是「实况−气候」。两者都有用，问题不同，不能偷换。

**误解 6：把单频定位误差直接叫 TEC 残差。**  
打假：定位误差还含对流层、多路径、几何等；未分离前不要等同。

### 8.10 本节朗读稿

模型给出平均肖像，数据给出当天脸。两者之差叫残差。残差可以是天气的化妆痕迹，也可以是算错年龄组的化验单，还可以是发烧时仍翻「健康人平均值」的方法错误。现象分析要求你把残差送上法庭：先问口径，再问旋钮与版本，最后才问物理。IRI 与 NeQuick 因此不是对手，而是可控的气候基线；GIM 与双频 STEC 不是自动真值，而是必须质控的实况近似。当你能写清「残差相对谁、排除了什么、还不能声称什么」，第四课才算接到了现象分析的接力棒。

## 9. 原理加厚：气候模型到底在「解」什么？

### 9.1 气候 vs 天气（再钉一次，落到可操作定义）

| | 气候肖像（IRI / NeQuick 族） | 天气实况（双频 STEC / GIM） |
|---|---|---|
| 问题 | 「这类太阳–地磁–季节–地方时条件下，平均 $N_e(h)$ 长什么样？」 | 「这一天、这条网、这些观测约束下，柱总量场是什么？」 |
| 输入 | 时间位置 + 指数/广播参数 + 系数表 | RINEX/产品 + 偏差与映射假设 |
| 输出 | 廓线与可积分 TEC | STEC/VTEC 场 |
| 暴期 | 可系统性失灵（方法边界） | 仍受站网/平滑限制，但是观测反演 |

**可操作定义**：若你关掉「今天的观测」，只留历书式指数与坐标，仍能给出几乎同一张图——你在用气候模型。若没有当天 GNSS（或掩星/测高仪同化），图就塌——你在用实况路线。

### 9.2 IRI 实际求解的状态：$N_e(h)$ 廓线，不是「一张 TEC 真值图」

IRI（International Reference Ionosphere）的核心交付是：**给定时间与位置，给出电子密度随高度的经验描述** $N_e(h)$（以及相关峰值参数等）。TEC 是廊线的**积分后果**：

$$
\mathrm{VTEC}_{\mathrm{model}}
=
\int_{h_{\min}}^{h_{\max}} N_e(h)\,\mathrm{d}h
$$

（斜路径则沿射线积分。）因此：

1. 你改 F2 峰密度或峰高，TEC 会变——但机理入口在廓线形状；  
2. 只比对 TEC、从不看 *h_mF2*/*N_mF2*，等于只看柱高不看「雾层堆在哪」；  
3. GNSS GIM 直接约束的是柱，对峰高可辨识性弱——**模型有廓线、GIM 有柱，二者可比但不可冒充同一观测**。

版本必须写清（如 `IRI-2026-package`、`IRI-2020-package`、`IRI-2016-package`，或包装 `iri2020`、`PyIRI`、`pyIRI2016`、`iricore`）。缺 `IRI-COMMON-FILES` / `IRI-indices` 是初学者「能编译、一跑就怪」的主因。在线入口 `CCMC-IRI-online` 同样要记版本与开关。扩展口径见 `IRI-Plas-SPIM-IZMIRAN`（引用须写明）。近实时更新气候的另一条路是 `GIRO-IRTAM` / `PyIRTAM`——仍不是 IGS GIM。

## 10. 驱动如何进入方程：把旋钮拧进 $N_e$

> 下列是**课堂直觉方程**，不是某一 Fortran 行的逐行翻译。目标：你能回答「F10.7 / Ap / 纬经时」各自拧的是肖像的哪一块。

### 10.1 总结构：坐标选点 + 指数选「哪本平均相册」

抽象成两步：

1. **几何–时间坐标** $(\varphi,\lambda,h,t) \text{（常再映到地磁纬、地方时、太阳天顶角 } \chi$）；  
2. **活动指数**（太阳：F10.7 / 黑子数等；地磁：Ap 等）决定在系数表里取哪一套「平均行为」。

人话：坐标告诉模型「你站在相册哪一页的哪个格子」；指数告诉模型「今天该翻『高太阳活动年的七月午后』那一本，还是『低年的安静夜』那一本」。

### 10.2 太阳活动（F10.7 / 黑子）：怎样抬整柱与峰密度

经验上，白天 F2 层峰密度与 TEC 基线随太阳活动升高。直觉写法：

$$
N_mF2 \;\sim\; \mathcal{F}(\varphi_{\mathrm{mag}},\,LT,\,season,\,F10.7,\ldots)
$$

- **F10.7 偏高**：许多地区白天 $N_mF2$ 与积分 TEC 的气候期望上移；  
- **填错日期或用错「日值/多日平均」**：整图系统性抬高或压低——残差图上像「全球平移」，很像旋钮事故而非新物理；  
- **暴期只猛拧 F10.7**：太阳代理≠磁暴电动力学；正负相分区、高纬沉降结构不会因此自动出现。

课堂实验：固定地点地方时，只扫 F10.7，看廓线峰与 TEC 单调抬升——这是在看**气候敏感度**，不是在「模拟一场暴」。

### 10.3 地磁活动（Ap 等）：有限修正，不是风暴解析解

部分 IRI 选项用地磁指数调节暴时平均行为。直觉：

$$
N_e^{\mathrm{(storm\;opt)}}(h)
=
N_e^{\mathrm{(quiet\;clim)}}(h)
+
\Delta N_e^{\mathrm{(stat\;storm)}}(h;\,Ap,\ldots)
$$

关键限制：

1. $\Delta N_e$ 来自**历史统计平均**，不是这次事件的同化场；  
2. 超级风暴可远超统计样本包络 → 残差巨大是**预期**；  
3. 若指数仍用平静默认却声称「驱动了暴」，残差法庭应判 **β（旋钮错误）**。

### 10.4 纬度 / 经度 / 时间：如何进入「地方时结构」

- **地理纬 + 地磁纬**：决定你落在赤道异常、中纬槽还是高纬域——许多经验式按磁纬组织。  
- **经度 + 世界时 → 地方时 LT**：同一世界时，东半球已是下午驼峰、西半球可能仍是上午。  
- **季节 / 年积日**：冬夏系数不同。  
- **太阳天顶角 $\chi$**：白天光致电离的几何开关；夜侧转用另一套衰减/维持经验。

直觉链：

$$
(t,\lambda)\mapsto LT,\quad
(\varphi,\lambda)\mapsto \varphi_{\mathrm{mag}},\quad
(LT,\chi,\varphi_{\mathrm{mag}},F10.7,Ap)\mapsto
\{N_mF2,\,h_mF2,\,\text{形状参数}\}
\mapsto N_e(h).
$$

### 10.5 高度：廓线形状比单 TEC 更「要命」的场合

HF 射线追踪、掩星对照、层析背景，需要 $N_e(h)$ 形状（峰高、半厚度、底层）。只匹配 TEC 而对错峰高，延迟与弯曲角仍可偏。教学上：先画正午/午夜廓线看峰是否离谱，再积分 TEC（`CCMC-IRI-online` / `PyIRI` / `iri2020` 皆可做演示，仍须记版本）。

## 11. NeQuick / NeQuick-G：与 IRI 的分工，以及 Az 参数直觉

### 11.1 NeQuick 族在解什么？

NeQuick（如 `NeQuick2-ICTP`、`Nequick-ITUR`、`NeQuickJRC`）同样给经验 $N_e$ 结构，工程上强调**沿任意射线积分 TEC/延迟方便**，故在传播、链路预算、ITU 场景常见。与 IRI 的课堂分工：

- IRI ≈ 参考标准肖像、参数丰富、社区对照基准；  
- NeQuick ≈ 传播与路径积分友好的经验廓线工具。  

二者都能积 TEC；不要说「只有 NeQuick 才有 TEC」。

### 11.2 Az（有效电离参数）直觉——太阳活动如何「塞进」NeQuick

NeQuick 常用一个与太阳活动相关的驱动（文献与实现中常称 **Az** 或由 F10.7/广播参数映射而来的有效电离水平）来缩放廓线强度。课堂骨架：

$$
N_e(h;\,\varphi,\lambda,t,\,Az)
\qquad\text{且}\qquad
\mathrm{STEC}=\int_{\mathrm{ray}} N_e\,\mathrm{d}s
$$

- **Az 升高** ≈ 「今天电离水平按更活跃的气候页来画」→ 峰与 TEC 基线上移；  
- **Az 不是 GNSS 观测同化**——它是经验驱动旋钮；  
- 科研 NeQuick2：你常手填/文件给定太阳代理再映到 Az；  
- **NeQuick-G**：Az（或等价电离参数）由 **Galileo 导航电文中的电离层参数** 在接收机侧生成——接口绑广播，不是你在脚本里随手改 F10.7 的同一条用户路径。

### 11.3 NeQuick-G 与 Galileo 单频

`Galileo-NeQuick-G` / `NequickG` / `NeQuickG-ESSR`：开放服务单频电离层改正口径。接收机用广播参数 + 链路几何估延迟。对照：

| 用户 | 策略 |
|---|---|
| 双频 | 组合消一阶；模型非必须 |
| GPS 单频（经典） | Klobuchar（`Klobuchar-study-code` / `Klobuchar.jl`） |
| Galileo 单频 | **NeQuick-G** + 电文参数 |
| 另一 Galileo 相关族 | `ntcmg`（NTCM-G，勿与 NeQuick-G 混名） |

纪律：禁止把 NeQuick2 参数硬塞进 Galileo 电文槽还自称合规；跨口径对比必须声明。`gri-iono` 可切换多模型接口，引用时写清选了哪一后端。`NeQuick2-MLF2` 等改写实现须谨慎对照官方。

### 11.4 「驱动进方程」对照表（背诵用）

| 驱动 | 进方程的直觉位置 | 拧错时的残差长相 |
|---|---|---|
| F10.7 / Az | 缩放 $N_m$ / 整柱气候水平 | 大范围近均匀偏置 |
| Ap 等 | 统计暴时修正项（若开启） | 该开没开 → 暴期残差爆炸；乱开 → 假暴结构 |
| 纬/磁纬 | 选择结构域（EIA/槽/高纬） | 驼峰位置、高低纬符号错 |
| 经度+时间 | 地方时 / $\chi$ | 日变化相位错（「东边的下午接到西边」） |
| 广播 NeQuick-G 参数 | 接收机侧 Az 等效 | 电文槽错 → 单频延迟整体漂 |
| 版本/公共文件 | 系数表本身 | 怪零、崩、不可复现 |

## 12. 残差判读加厚：物理信号 vs 模型天花板

### 12.1 定义与法庭顺序（复习并加判据）

$$
R = X_{\mathrm{data}} - X_{\mathrm{model}}
$$

**先 γ（口径）→ 再 β（旋钮/失灵）→ 最后 α（物理）。**

| 判决 | 关键判据 |
|---|---|
| γ 假残差 | STEC 减竖直；时标/经度乱；积分高度口径不一；把单频改正输出当 VTEC |
| β 失灵/旋钮 | 指数日期错；缺 `IRI-COMMON-FILES`/`IRI-indices`；NeQuick2↔G 混用；残差随你改 F10.7 整体滑、却不随 Dst 窗口走 |
| α 物理天气 | 与主相/恢复相对齐；空间型像正负暴/EIA 变形；换 GIM/换质控站仍同号；指数版本已核对 |

### 12.2 「模型天花板」是什么意思？

经验气候模型的表达能力有上限：平滑大尺度、统计平均、对突发 TID、泡、超级风暴精细结构**本来就不会**。天花板的操作化信号：

1. 强扰动期 $|R|$ 系统变大，且模型绝对场仍「平静漂亮」；  
2. 你提高 F10.7/Ap 只能整体平移或轻度变形，**造不出**观测上的分区锋面；  
3. 残差空间型跟着数据走，不跟着你改模型开关的时间戳走。

此时正确叙事：**「气候模型达到天花板；残差度量偏离气候的幅度」**——不是「IRI 表征了该暴的精细结构」。

### 12.3 合法残差工作流（逐步）

1. **数据侧**：质控双频 VTEC，或同档 GIM（`CDDIS-IONEX` + `ionex` / `ionex_reader`；近实时 `ESA-TIO-NRT-TEC` / `NOAA-SWPC-GloTEC` / `CAS-BDsmart-RTS-Iono` 仅快看）。  
2. **模型侧**：写死版本（`IRI-2026-package` / `iri2020` / `PyIRI` 或 `NeQuick2-ICTP`）；配齐公共文件与指数；Galileo 场景用 `Galileo-NeQuick-G` 等。  
3. **对齐**：同为 VTEC 或同一射线 STEC；同时刻；声明积分限。  
4. **可视化**：对称色标；同时保留数据与模型绝对场（`DiffIonMap`、`mgfernan-pygnss`、`gri-iono` 可辅助）。  
5. **开庭问题**：改 F10.7 是否只整体平移？稠密区与空洞区是否一样「精细」？残差是否贴 Dst/Kp？空间型是否像文献正负暴而非截断斑？

### 12.4 与安静日 GIM 差值的分工

| 基线 | 做法 | 含义 |
|---|---|---|
| 安静日 GIM | 风暴 GIM − 安静 GIM | 相对近期安静**实况**的天气差（03） |
| IRI/NeQuick | 数据 − 模型 | 相对**气候肖像**的偏离（本节） |

作业建议：同一事件两张图都交，并写同号/异号区可能原因。

### 12.5 何时模型 **MUST NOT** 当风暴个例真值

出现任一即暂停「模型=真值」：

1. 目标是「事件期间 TEC 变化/精细结构」；  
2. 强扰动指数窗口，却只用平静气候默认；  
3. 需要小尺度梯度/闪烁，模型只有平滑气候；  
4. 说不清版本与指数；  
5. 审稿人问观测在哪时只能指模型图；  
6. 残差已显示天花板，仍把模型等值线当锋面证据。

**正确组合**：模型作气候基线或单频改正；GIM/STEC 作实况近似；残差作偏离度量——三者标签不许撕掉。

## 13. 驱动–残差联合练习（无代码口述版）

**练习 1**：固定 IRI 版本，安静日中纬正午，扫 F10.7。预期：TEC 气候值单调变；与同日 GIM 的残差主要呈近似偏差。若扫 F10.7 时出现「移动的窄锋」，先查经度/地方时 bug（γ）。

**练习 2**：主相日，正确填 Ap/F10.7，仍见东亚大片正残差、某夜侧负残差，且换一家 GIM 同号。倾向 α；仍须写「相对 IRI-某版气候」。若把 Ap 改回 0 残差更大但空间型差不多，说明指数修正未抓住事件——天花板叙事。

**练习 3**：Galileo 单频仿真。用 `Galileo-NeQuick-G` 与电文参数；不要用 NeQuick2 残差评价「官方单频改正性能」除非题目就是跨口径。

**练习 4**：故意制造 β——指数错一天。残差应接近大尺度偏置；若你把它写成「发现旅行离子层扰动」，不及格。
