## 先问你要解决什么

| 你的目标 | 更像哪一类 |
|---|---|
| 把多站 TEC 收成一张图 | GIM / 插值（[03](./03-gim-ionex.md)、[10](./10-build-gim-workflow.md)） |

名字混用，是读论文时最容易晕的地方。

---

## 一句话定义

**同化** = 模式先给出背景电离层状态；再根据观测（GNSS STEC/VTEC、测高仪、掩星等）和误差设定，更新状态，使分析场与后续预报更接近真实。

它不是：

- 把 IONEX 直接贴到地球表面；
- 也不是「训练一个明天 TEC 的网络」——后者可以借鉴同化思想，但机制不同。

---

## 最小框图（请能默画）

```
经验/物理模式  --时间预报-->  背景场 x_b
                                 │
GNSS / 测高仪 / 掩星 --观测算子 H--> 创新 d = y − H(x_b)
                                 │
                            分析更新 → x_a
                                 │
                            作为下一时刻初值再预报
```

课堂三问：

1. \(x\) 是什么？VTEC 格网、球谐系数，还是三维 \(N_e\)？  
2. \(y\) 是什么？斜路径 STEC 还是垂直 VTEC 产品？  
3. \(H\) 怎么做？路径积分？映射函数？

答不上这三问，就还没读懂那篇「assimilation」论文。

---

## 三个必须懂的词

1. **背景场 \(x_b\)**：IRI / NeQuick 便宜；`TIE-GCM`、`GEMINI3D` 更重但物理更丰。  
2. **观测算子 \(H\)**：从模式状态正演出 STEC——和层析正演是亲戚。  
3. **权重 / 增益**：观测准、模式飘 → 多信观测；测站稀、模式有气候约束 → 不能把分析拉爆。

## 常见误区

- 把 GIM 克里金插值叫做 4D-Var。  
- 只用一个分析中心的 IONEX 当「真值」去同化，再拿它验证——循环论证。  
- 忽略 DCB：观测算子再漂亮，STEC 基准歪了，分析场会整层偏（回 [09](./09-dcb-biases-deep.md)）。
