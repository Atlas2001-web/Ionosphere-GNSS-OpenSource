# 12 · 数据同化入门：模式与 GNSS 观测如何「握手」

> 前置：[04 IRI/NeQuick](./04-iri-nequick.md) · [11 层析](./11-tomography-basics.md)

---

## 一句话定义

**同化**：模式先给出背景电离层状态；再根据观测（GNSS STEC/VTEC、测高仪、掩星等）及各自误差，更新状态，使下一时刻更接近真实。

它不是：

- 把 IONEX 直接贴到地球表面；
- 也不是单纯训练一个「明天 TEC」神经网络（那是预报/拟合，可借鉴同化思想，但名字别混用）。

---

## 最小框图（请能默画）

```
物理/经验模式  --预报-->  背景场 x_b
                              │
GNSS/测高仪/掩星 --观测算子 H -->  创新（观测 − 正演）
                              │
                         分析更新 x_a
                              │
                         作为下一时刻初值
```

你要能指出：GNSS STEC 是通过怎样的 \(H\)（路径积分）进系统的。

---

## 三个必须懂的词

1. **背景场**：IRI 可以当廉价背景；`TIE-GCM` / `GEMINI3D` 更重但物理更丰。  
2. **观测算子**：从三维 \(N_e\) 正演出 STEC —— 和层析正演是亲戚。  
3. **权重**：观测很准且模式很飘 → 多信观测；赤道测站稀、模式有气候学约束 → 不能把分析拉爆。

## 和本仓库的连接方式

| 角色 | 示例入口 |
|---|---|
| 经验背景 | IRI 系列、`PyIRI`、Galileo NeQuick-G |
| 物理背景 | `TIE-GCM`、`GEMINI3D`、SAMI 相关条目 |
| 观测产品 | `CDDIS-IONEX`、`DLR-IMPC`、ESA TIO、掩星/测高仪数据集 |
| 数据怎么下 | [`docs/data-access.md`](../data-access.md) |

机器学习 TEC 预报仓（目录里若干 IonCast / 预报类）归 **预报工具**，读论文时看它吃什么特征、验证是否泄漏未来信息，不要自动写成「同化系统」。

## 入门练习（不写代码也能做）

1. 选一篇「assimilate GNSS TEC」论文，画出它的 \(x\)、\(y\)、\(H\)。  
2. 问自己：更新的是 VTEC 格网、球谐系数，还是三维 \(N_e\)？  
3. 到本仓库 list 里各找一个「可当背景」和「可当观测」的条目。
