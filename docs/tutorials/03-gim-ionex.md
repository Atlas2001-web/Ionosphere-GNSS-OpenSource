# 03 · GIM 是什么？IONEX 文件里有什么？

> **课堂定位**：接 01（TEC 概念）与 02（双频估 STEC）。你已经会说「斜的是 STEC、竖的是 VTEC」。这节课回答：别人给你一张「全球电子含量图」时，它是什么、怎么读、和你自己算的站星 STEC 是什么关系、文件叫 IONEX 时头和身子各写什么。
>
> **写给谁**：第一次下载 `*.inx` / IONEX、第一次听到 CODE/JPL/UPC/WHU、第一次把 GIM 当成「真值」或把格网点 VTEC 当成自己斜路径 TEC 的人。

---

## 1. 这节课解决什么问题（生活 / 工程）

### 1.1 三个会真实卡住你的现场

**现场甲：领导说「把今天全球 TEC 图画出来」。**  
你打开搜索，跳出 GIM、IONEX、IGS、Final、Rapid、球谐……你不知道该下哪家、哪个文件名、图上的颜色代表什么。其实领导要的常常是：**某一时刻、全球或区域的 VTEC 场**——也就是 GIM 产品；交换格式最常见的就是 IONEX。

**现场乙：你把双频估出的某站某星 STEC，和 GIM 图上「同站」的数一比，差了十几 TECU。**  
有人说你算错了，有人说 GIM 不准。更常见的真相是：你在比**斜路径柱**和**格点竖直柱**，还可能没对齐时间、壳高、偏差改正与插值方式。

**现场丙：业务要「准实时」，你下了三天前的 Final 产品。**  
Final 往往更稳，但时延长；Rapid / NRT 时延短，误差与平滑策略可能不同。选错时延档，值班图会「看起来很漂亮，却已经过期」。

### 1.2 这节课的交付物

学完你应能：

1. 用一句话区分 **GIM**、**STEC**、**VTEC**；  
2. 打开一份 IONEX，指出头段与数据段各自管什么；  
3. 解释格网图怎么读（经纬、时间片、单位缩放）；  
4. 说出球谐展开与直接格网的直觉差别；  
5. 点名若干 IGS 分析中心，并知道 Final / Rapid / NRT 时延档；  
6. 列出至少五条读图与对比时的坑；  
7. 在本仓库 `PROJECTS.json` 里用**真实 `name`** 对照「下图 / 读图 / 建图」三类工具。

### 1.3 边界（先划清，避免跑题）

- 本课**不**教你从 RINEX 估 STEC（那是 02）。  
- 本课**不**把 IRI/NeQuick 当 GIM（那是 04：气候模型 ≠ 当天实测图）。  
- 本课**不**把闪烁指数当 TEC 图（那是 05）。  
- GIM 是**产品**，不是实验室绝对真值。

## 2. 完整词表（每个术语人话定义）

老师要求：第一遍快速扫；主讲解后再回看。缩写只是板书压缩，口头尽量说中文全称。

### 2.1 观测量与图产品

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **STEC** | 沿卫星视线「斜着」积出来的电子柱 | Slant TEC；站–星一对一 |
| **VTEC** | 换成「竖直往天顶看」的等效电子柱 | Vertical TEC；地图产品常用 |
| **TEC 图 / 离子图** | 把某区域 VTEC（或相关量）画成颜色场 | 常按时间切片 |
| **GIM** | 全球（或大区域）电离层图产品 | Global Ionosphere Map；格点多为 VTEC |
| **区域 GIM** | 只覆盖一块大陆/国家的图 | 分辨率常更高，边界外勿乱用 |
| **穿刺点 IPP** | 斜线戳到假定薄壳上的点 | 建图时常把 STEC 信息钉在 IPP |
| **薄壳高度** | 假装电子都挤在某一高度的壳上 | 文件头常写；常见约 450 km 量级，以文件为准 |
| **映射** | STEC ↔ VTEC 的换算 | 低仰角时最容易出事 |

### 2.2 IONEX 与文件

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **IONEX** | 电离层图的常见文本交换格式 | Ionosphere Map Exchange；像「按时间切的 VTEC 网格表 + 元数据」 |
| **头段（header）** | 文件开头说明「这张表怎么读」 | 时间、格网、单位、中心、壳高等 |
| **数据段（body）** | 真正的数字格子 | 每个历元一张（或一层）格网 |
| **历元 / 时间片** | 某一时刻那一张图 | 常见 1 h / 2 h，以头为准 |
| **格网** | 经纬度按步长排开的点阵 | 如经度 5°、纬度 2.5° 等 |
| **EXPONENT** | 告诉你整数要乘多少次幂才还原 | 常见与「0.1 TECU」编码相关，**以头说明为准** |
| **RMS 图** | 「不确定度/离散度」的伴生格网 | 不是第二张 TEC；有则更好做质控 |
| **BASE RADIUS / HGT** | 地球半径或壳高一类几何参数 | 影响你如何理解映射与高度假设 |

### 2.3 建图语言与机构

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **格网 GIM** | 直接在经纬网上给 VTEC | IONEX 里你最常看到的样子 |
| **球谐 / 函数展开** | 用一组全球「旋钮」（系数）描写平滑场，需要时再合成到格网 | spherical harmonics；存储紧、偏全球平滑结构 |
| **分析中心 AC** | 真正干活出产品的单位 | Analysis Center；如 CODE、JPL、UPC、WHU、CAS、GFZ 等 |
| **IGS** | 国际 GNSS 服务组织框架 | 综合产品常由多中心结果组合 |
| **IAAC** | 电离层分析中心 | Ionosphere Associated Analysis Centers |
| **IGS 综合 GIM** | 「多家意见汇总」后的官方味道产品 | 与单中心产品应分开引用与评估 |
| **Final** | 事后最终档，时延较长，通常更稳 | 论文对比常用 |
| **Rapid** | 快速档，时延较短 | 业务与准实时科研常用 |
| **NRT / Ultra / RTS** | 近实时或更激进的快产品 | 名称因中心而异；精度与平滑策略可能不同 |
| **Latency 时延** | 从观测日到你拿到文件要等多久 | 选产品时第一优先级之一 |

### 2.4 词表纪律

1. **禁止**把 GIM 格点 VTEC 口头说成「我的 STEC」。  
2. **禁止**不看头段就假设单位一定是 TECU 整数。  
3. **禁止**把 Final 与 Rapid 当成同一个数的两个文件名。  
4. **允许**先把 IONEX 想成「天气预报格点图」，但必须在误解节纠正细节。

## 3. 主讲解：类比、分步骤、「常见误解」专节

### 3.1 先回答灵魂问题：GIM 和 STEC/VTEC 到底啥关系？

请记住三层：

1. **STEC**：某一接收机看某一颗卫星，斜路径上的柱总量（02 课主产物）。  
2. **VTEC**：把斜的换算/建模到竖直方向后的量；地图友好。  
3. **GIM**：把很多站、很多星、很多 IPP 上的信息，建成**空间连续的 VTEC（等）场**，再按时间切片发布。

类比（贯穿全课）：

- 单站温度计读数 ≈ 你的 STEC/VTEC 采样；  
- 全国气温格点图 ≈ GIM；  
- 把格点图存成标准文本给别人用 ≈ IONEX。

所以：GIM **不是**「某一站星的 STEC 时间序列」；它是「空间场」。你要站星序列，回 02；你要插值改正、画全球图、和别人交换，才进 03。

### 3.2 步骤：从「一堆 STEC」到「一张 GIM」的头脑流程

不必当堂写代码，但脑子里要有流水线：

**步骤 A**：各站双频观测 →（周跳、平滑、DCB 等）→ STEC。  
**步骤 B**：几何 + 薄壳 → 把信息放到 IPP（经纬 + 壳高）。  
**步骤 C**：用格网插值、球谐、或局部基函数，把离散约束变成连续场。  
**步骤 D**：按时间间隔输出格网，写成 IONEX（或中心内部格式再导出）。  
**步骤 E**：用户下载 → 读头 → 解码 → 在任意经纬插值 → 得到该点 VTEC 时间序列。

人话：GIM 生产是「从许多斜管子的读数，估计一整片雾的厚度图」；你读 GIM 是「从图上查某点竖直厚度」。

### 3.3 类比加深：雾场、探头与天气预报图

把电离层想成一层会随地方时、纬度、太阳活动变厚变薄的雾。

- GNSS 链路 = 一根根斜穿雾的探头；  
- STEC = 探头路径上的「雾柱积分」；  
- 映射到 VTEC = 换算成「竖直标准厚度」方便画平面图；  
- GIM = 气象台发布的「雾厚分析场」；  
- IONEX = 把分析场按规范装箱的快递单 + 货物。

探头密的地方（欧洲、北美、东亚部分区域）图往往更可信；海洋、极区、测站稀疏处，图更「靠模型/平滑补全」——颜色仍很漂亮，但别过度解读小尺度碎斑。

### 3.4 IONEX：头段你至少要会找什么？

打开文本，先找头，不要直接盯数字。初学者清单：

1. **时间范围与间隔**：从哪天几点到哪天几点？每隔多久一张？  
2. **经纬度定义**：起点、终点、步长；注意经度是 −180～180 还是 0～360。  
3. **高度 / 壳高相关行**：薄壳假设写多少？  
4. **EXPONENT / 单位说明**：整数如何还原成 TECU？  
5. **分析中心、产品类型**：哪家 AC？Final 还是 Rapid？  
6. **是否有 RMS 图、多少张 map**：有助于质控与脚本循环。

人话：头段是「说明书」；说明书没读完就画彩色图，等于没看坐标轴就发表。

### 3.5 IONEX：数据段怎么读一张 map？

典型直觉（具体关键字以规范与文件为准）：

- 每个历元开始有标记（时间戳一类）；  
- 然后按纬度带（或规范规定的次序）列出该带上各经度的 TEC 整数；  
- 读软件用头里的 EXPONENT 等还原成浮点 TECU；  
- 你的任务常是：给定 (时间, 纬, 经) → 在时间与空间上插值 → 得到 VTEC。

读图口诀：

1. 先定时间片（或夹在两个历元之间插值）；  
2. 再定经纬落在哪四个格点之间；  
3. 双线性（或软件默认）插值；  
4. 看旁边有没有 RMS，避免把噪声当结构。

### 3.6 球谐 vs 格网：两种「建图语言」

| 思路 | 直觉 | 你常看到的产物 |
|---|---|---|
| **格网** | 直接在经纬网上填 VTEC | IONEX 格网点，画图直观 |
| **球谐 / 函数展开** | 用有限个全球基函数系数描写平滑场 | 系数文件；需要时再合成格网/IONEX |

类比：

- 格网像「照片像素」；  
- 球谐像「用少数旋钮调一幅平滑全球曲面」。

球谐擅长全球尺度、平滑结构、存储紧；对很局部的锋利梯度，高阶不够时会抹平。格网直观、区域加密方便，但文件更大，海洋空洞处仍可能被平滑填满。

很多流水线是：**STEC →（在 IPP 约束下）解球谐或局部基 → 输出格网 IONEX**。所以你下载到的 IONEX，背后可能经历过球谐；文件本身却常常是格网形态。

### 3.7 IGS 分析中心：你不是只认识「一个官方」

IGS 电离层工作组框架下，多家 IAAC 例行出图，再可能形成综合产品。本仓库数据集侧已点名的入口包括（名称均为 `PROJECTS.json` 真实 `name`）：

- 下载总入口味道：`CDDIS-IONEX`、`IGS-Ionosphere-WG`、`IGS-Products`、`NASA-Earthdata-Login`（CDDIS 需登录）；  
- 单中心/相关：`CODE-AIUB-Analysis-Center`、`CODE-AIUB-Product-Download`、`JPL-IONEX-Rapid`、`UPC-IONEX-Archive`、`WHU-IGS-Ionosphere-AC`、`GFZ-Global-Ionosphere-Maps`、`CAS-BDsmart-Iono-Products`、`CAS-BDsmart-RTS-Iono`、`ROB-IONEX-Products` 等。

课堂纪律：**引用时写清中心 + 产品档（Final/Rapid/…）+ 日期**，不要只写「IGS TEC」。

### 3.8 时延档：Final / Rapid / NRT

用快递类比：

- **Final**：慢件精装，适合论文「当天实况分析」对比；  
- **Rapid**：次日达，适合多数业务回顾；  
- **NRT / Ultra / RTS**：几乎当日达或更快，适合值班与试验；可能更吵、更平滑、或策略不同。

选档口诀：

1. 要事后精密对比 → 优先 Final（并声明中心）；  
2. 要较快闭环 → Rapid；  
3. 要准实时 → NRT/RTS，但必须做多源交叉与降级策略；  
4. **永远不要**用三天前的 Final 假装「现在的空间天气」。

### 3.9 专节：常见误解（请课堂投票打假）

**误解 1：GIM 上读到的数就是我的 STEC。**  
错。GIM 格点通常是 VTEC 场。你的链路是斜的；要用映射/射线穿过场积分等，不能直接把同经纬 VTEC 当 STEC。

**误解 2：所有 IONEX 数字直接就是 TECU。**  
错。常见有整数×指数缩放（如 0.1 TECU 量级编码）。不读 `EXPONENT` 就会差十倍。

**误解 3：CODE、JPL、UPC、综合产品应该一模一样。**  
错。测站集、DCB 策略、映射、球谐阶数、时间分辨率都不同。差几个 TECU 很常见；差很多才要排查。

**误解 4：颜色好看 = 小尺度结构都真。**  
错。平滑与基函数会抹掉或伪造纹路。海洋与测站空洞处尤其危险。

**误解 5：壳高写 450 km，所以电子真的都在 450 km。**  
错。薄壳是压缩三维到二维的假说，方便建图与映射，不是物理薄饼。

**误解 6：有了 GIM 就不用改 DCB 了。**  
错。GIM 生产过程已处理偏差，但你自己的 STEC 流水线仍要按 02 课处理；拿自建 STEC 和 GIM 比时，偏差策略不一致会系统性抬高/压低。

**误解 7：Final 永远优于 Rapid，所以任何场景都下 Final。**  
错。Final 更稳但时延长；实时业务用 Final 等于看旧报纸。

**误解 8：区域加密 GIM 可以外推到全球。**  
错。区域产品出界勿用；边界附近插值也要警惕。

### 3.10 对比实验的正确姿势（头脑清单）

若你有同站双频 STEC，想和 GIM 比：

1. 时间对齐（插值到同一历元）；  
2. 把 STEC 映射成 VTEC，或把 GIM VTEC 映射/积分到斜路径——**两边统一到同一物理量**；  
3. 声明壳高、仰角截止、映射函数；  
4. 低仰角时段单独评估（差异通常更大）；  
5. 多中心交叉，不要只盯一家；  
6. 记录你用的 IONEX 文件名与 AC。

### 3.11 坑位清单（Pitfalls，建议打印贴显示器）

1. 单位/EXPONENT 读错 → 数量级灾难。  
2. 经度 0～360 与 −180～180 混用 → 太平洋附近「镜子错误」。  
3. 时间是 GPS 时、UTC 还是其他？插值前先统一。  
4. 把 RMS 图当 TEC 图画进论文。  
5. 用预测/预报产品当分析场真值。  
6. 忽略等离子体层贡献差异（不同产品口径可能不同）。  
7. 脚本只读第一张 map，忘记按历元循环。  
8. 下载未登录 CDDIS（`NASA-Earthdata-Login`）导致「目录在、文件下不来」。  
9. 文件名里的年积日/GPS 周搞错一天。  
10. 把气候模型（04 课）输出的 TEC 当成 IGS GIM。

## 4. IONEX / GIM 的输入输出与文件、调用直觉

### 4.1 对「生产者」：输入 → 输出

| 方向 | 典型内容 |
|---|---|
| **输入** | 全球/区域 GNSS 网 RINEX（或多中心已估 STEC）、卫星/接收机偏差产品、轨道/钟差、映射与壳高设定、可选约束 |
| **处理** | 质量控制 → IPP 建模 → 格网或球谐估计 → 时间平滑 |
| **输出** | IONEX（VTEC 格网 ± RMS）、有时还有系数文件、监控网页图 |

### 4.2 对「使用者」：你的输入 → 你的输出

| 你提供 | 软件/脚本做的事 | 你得到 |
|---|---|---|
| IONEX 路径 | 解析头与各历元格网 | 内存中的三维/多片场（时×纬×经） |
| 时间 + 纬 + 经 | 时空插值 | 该点 VTEC（TECU） |
| 可选：仰角/方位 + 壳高 | 映射到斜路径 | 近似 STEC（用于单频改正等） |
| 两份 IONEX | 差分、统计 | 中心间差异、自建 vs 官方差异 |

调用直觉：把 IONEX 读库当成「天气预报 NetCDF 的电离层亲戚」——先 load，再 sel/interp，再 plot。不要手写正则硬拆，除非你在写解析器本身。

### 4.3 三种角色不要按成一个按钮

1. **下图**：数据门户 / downloader；  
2. **读图 / 画图 / 插值**：ionex 读库与可视化；  
3. **建图**：mosgim 一类 GIM/球谐工具。  

「我安装了一个叫 ionex 的包」≠「我会生产 IGS Final」。

## 6. 课堂检查题 + 答案

**题 1**：GIM 格网点上最常见的是 STEC 还是 VTEC？为何不能直接当站星 STEC用？  
**答**：常见为 VTEC。STEC 是斜路径、针对具体站星；要用映射或沿射线积分，并声明壳高与仰角。

**题 2**：IONEX 头里不看 EXPONENT 最大的风险是什么？  
**答**：单位缩放读错，结果整体乘错（例如 0.1 倍或 10 倍），图仍「形状像样」但数值废掉。

**题 3**：球谐与格网各擅长什么？  
**答**：球谐用系数描写全球平滑场、存储紧；格网直观、易插值与区域加密。IONEX 用户侧常看到格网，背后可能经历球谐。

**题 4**：Final 与 Rapid 怎么选？  
**答**：事后精密对比偏 Final；要较短时延偏 Rapid；准实时看 NRT/RTS。引用必须写清档与中心。

**题 5**：举出本仓库三个读 IONEX 的真实 `name`、两个数据入口 `name`、一个建图类 `name`。  
**答示例**：读：`ionex`、`ionex-rs`、`ionex_reader`；入口：`CDDIS-IONEX`、`JPL-IONEX-Rapid`；建图：`mosgim`（或 `mosgim2`）。

**题 6**：为何低仰角时段「自建 VTEC vs GIM」更容易打架？  
**答**：映射误差放大、多路径与观测噪声更大、IPP 落点更远，薄壳假设更伤。

**题 7**：把 RMS 图当 TEC 画进论文错在哪？  
**答**：RMS 是不确定度/离散度伴生场，不是电子含量本身。

**题 8（开放简述）**：用气象类比说明 GIM 与单站 STEC 的关系。  
**答要点**：单站采样 vs 格点分析场；分析场有平滑与空洞填补；不能把格点气温当成你手里那根温度计在另一地点的读数而不做换算。

## 8. 用 GIM 差值图做现象分析：风暴日 − 安静日（详细走查）

> **本节目标**：把 01 课「必须有基线」与 03 课「会读 IONEX」焊在一起。现象分析里最常用、也最容易被滥用的工具，就是**差值图**：扰动日（或风暴日）减去安静日（或安静平均）。做对了，正负暴、区域响应、地方时结构一目了然；做错了，色标与时延档会帮你「造出」假风暴。

### 8.1 先补词表：差值图专用

| 术语 | 人话 | 稍严一点 |
|---|---|---|
| **差值图 / 差分图** | 两张（或两组）VTEC 场相减后的图 | ΔVTEC(λ,φ,t) = VTEC_event − VTEC_base |
| **风暴日 / 事件日** | 你关心的扰动日期 | 写清指数与主相时间 |
| **安静日基线场** | 对照用的 VTEC 场 | 单日或多日平均 |
| **正异常 / 负异常** | 差值 >0 / <0 的区域 | 相对基线，不是绝对「TEC 高」 |
| **同地方时比较** | 比较时对齐「当地几点」而不只对齐世界时钟面 | 减少把昼夜差当成风暴 |
| **同产品约束** | 相减的两边来自同一 AC、同一档 | 避免把中心间偏差当成地球物理 |
| **色对称** | 正负用对称色标（如 ±30 TECU） | 防视觉夸大单侧 |
| **空洞泄漏** | 测站稀处平滑场相减仍漂亮 | 差值也可能是产品噪声结构 |

**词表纪律：** 差值图标题必须写「谁减谁、哪家产品、哪个时刻」；只写「TEC anomaly」而不写基线，作业不合格。

### 8.2 为什么要减？一张图讲不清「相对谁」

绝对 VTEC 图永远带着强大的气候日变化：下午高、夜里低、低纬驼峰。你盯着风暴日下午的红斑大喊「暴了」，可能只是普通地方时结构。减去安静日同一世界时（或更好：同一地方时结构）后，**气候底子被大致掀掉**，剩下的才更接近「这件事多出来的笔迹」。

类比：两张旅游照片都有蓝天。要证明「今天多了一朵奇异的云」，最好叠差或闪烁对比，而不是单看一张说「哇好蓝」。

### 8.3 详细走查：从选日到出图（头脑流水线，可当作业步骤）

下面按「实验室值班主任」口吻走一遍。工具名均为 `PROJECTS.json` 已核验的 `name`。

#### 步骤 0：写科学问题（一句话）

合格例：「主相期间，东亚中纬日侧 VTEC 相对安静日平均偏高还是偏低？偏多少 TECU？」  
不合格例：「画一下风暴 TEC。」

#### 步骤 1：锁定事件日与指数窗口

1. 记下风暴日日期、主相大致起止（UTC）。  
2. 用 `GFZ-Kp-Index`、`NOAA-SWPC-Planetary-K`、`NASA-OMNIWeb` 等确认不是「日历上有个名字但指数很平」。  
3. 在笔记本画时间轴：初相 / 主相 / 恢复相（能粗分即可）。

#### 步骤 2：挑选安静日基线

回顾 01 课标准，并加两条 GIM 专用约束：

1. 尽量与事件日季节接近；  
2. **基线日必须有同一 AC 的同档 IONEX 可下载**（不要事件日用 CODE Final、基线日却只有别家 Rapid）。  
3. 推荐 3～5 个安静日；若时间紧，至少 1 个经指数确认的安静日，并在文中承认局限。

#### 步骤 3：下载并身份核对

1. 入口：`CDDIS-IONEX`（常需 `NASA-Earthdata-Login`）、或 `JPL-IONEX-Rapid`、`UPC-IONEX-Archive`、`CODE-AIUB-Product-Download`、`CAS-BDsmart-Iono-Products`、`WHU-IGS-Ionosphere-AC`、`GFZ-Global-Ionosphere-Maps`、`ROB-IONEX-Products` 等。  
2. 每个文件打开头：AC、时间、格网、EXPONENT、壳高、是否 RMS。  
3. 读库：`ionex`、`ionex_reader`、`ionex-rs`、`MathWorks-ionex_reader`、`Ionex_Parser`。  
4. **禁止**跳过 EXPONENT。

#### 步骤 4：时间对齐到同一套切片

1. 选定要分析的世界时列表（例如主相每 2 小时一张）。  
2. 事件场与基线场都插值到这些时刻。  
3. 若基线是多日平均：先对每个安静日插值到同时刻，再平均，得到 \(\overline{\mathrm{VTEC}}_{\mathrm{quiet}}(t)\)。  
4. 检查：经度定义是否统一（0～360 vs −180～180）。

#### 步骤 5：做减法（核心一行）

对每个时刻：

\[
\Delta\mathrm{VTEC}(\lambda,\varphi,t)=\mathrm{VTEC}_{\mathrm{storm}}(\lambda,\varphi,t)-\overline{\mathrm{VTEC}}_{\mathrm{quiet}}(\lambda,\varphi,t)
\]

人话：同一格点、同一时刻，风暴减安静。  
本仓库与差分制图相关可点名 `DiffIonMap`（用法以项目文档为准）；你也可以在 `ionex` / `ionex_reader` 读入后自行数组相减再画。

#### 步骤 6：上色与读图（强制规范）

1. **对称色标**：例如 −40～+40 TECU，零为中性色。  
2. 同时保留一张绝对 VTEC 图作附录，防止差值「看起来有、绝对场其实是产品空洞」。  
3. 按 01 课长相分类：整体抬升？驼峰变形？分区正负？波纹？  
4. 写句子模板：「在 `某AC` Final、`某UTC`，相对 N 日安静平均，某某区域 ΔVTEC 约为 +/− M TECU，表现为……」

#### 步骤 7：交叉验证（差值图也要打假）

1. **换一家 AC** 重做同一差值，符号与大尺度结构是否稳定？  
2. **换一个安静日集合**，结论是否崩？  
3. **与单站 STEC**（经 02 课 QC）映射后对比：同区域是否同号？  
4. 海洋/极区大斑块降级表述：「产品提示可能，待测站验证」。  
5. 可选：用 `ESA-TIO-NRT-TEC`、`NOAA-SWPC-GloTEC` 等近实时产品做定性对照，但勿与 Final 混称为同一精度。

#### 步骤 8：把差值图嵌回现象叙事

差值图不是终点，是证据板。完整叙事顺序建议：

1. 指数：何时暴；  
2. 绝对场：当天气候+天气长什么样；  
3. 差值场：相对安静多了/少了什么；  
4. 一致性：多中心、多站；  
5. 局限：壳高、平滑、测站空洞、时延档。

### 8.4 走查示例（虚构数字，只练口气）

> 事件：某年某月某日磁暴主相。产品：某 AC Final（经 `CDDIS-IONEX`）。基线：主相前两周内三个低 Kp 日的同时刻平均。  
> 结果：世界时 12:00，东亚中纬出现大范围正异常约 +8～+15 TECU；同时刻欧洲夜侧接近 0～弱负。  
> 表述：这是「分区、地方时依赖的相对变化」，不是「全球 TEC 暴涨」。  
> 若换 UPC 与 CODE 两家差值，东亚正异常仍在、幅度差约 3 TECU → 大尺度结论可保留，精细等值线不写死。

### 8.5 差值图常见误解与坑

**误解 1：差值图红就是「TEC 很高」。**  
打假：红只表示比基线高；绝对 TEC 可能仍低于另一季节的安静下午。

**误解 2：任意两天相减都叫风暴研究。**  
打假：基线必须安静且产品对齐；乱减会把季节差、太阳旋转周差异当成暴。

**误解 3：Final 减 Rapid 也能看结构。**  
打假：档次与滞后不同，系统差可能进差值。

**误解 4：色标不对称没关系。**  
打假：只显示 0～30 会让弱负异常消失，造成「只有正暴」的假叙事。

**误解 5：差值光滑 = 物理光滑。**  
打假：球谐/平滑会制造大尺度漂亮斑；对照 RMS 图与测站密度。

**误解 6：有了差值图就不用单站 QC。**  
打假：GIM 是产品；关键结论仍应用 02 课质控过的站星交叉。

**坑：经度镜像。**  
0～360 与 −180～180 混用时，太平洋两侧差值会「鬼影」。相减前统一经度。

**坑：只减第一张 map。**  
脚本忘了按历元循环，会得到一张「永远同一时刻」的假时间序列。

### 8.6 与建图工具的关系（你是用图的人，还是造图的人）

- **用官方图做差值：** `CDDIS-IONEX` + `ionex` / `ionex_reader` 足够支撑本课走查。  
- **自己建 GIM 再减：** 才需要 `mosgim`、`mosgim2`、`m_gim`、`M_GIM`、`SH-GIM` 等——那是进阶，且必须把 DCB、壳高、站网写进方法。  
- **差分可视化专项：** `DiffIonMap`、以及画图类 `IonMap`、`INPE-TEC-Maps-IONEX` 等，按需选用，勿假设按钮等价。

### 8.9 本节朗读稿

全球离子图是实况分析场；安静日是对照组；两者相减，才把「相对这件事多出来的笔迹」写到地图上。走查顺序是：问题→指数→选安静→下载核对→时间对齐→相减→对称色标解读→多中心多站打假→写带局限的句子。差值图很美，但美不是证据；证据是可重复的减法与过关的一致性。
